# 情景设置设计

2026-09-17 · 产品约定与待实施设计。现有界面、计算和分享代码尚未按本文改造。

## 定位

原“靶标”功能统一改名为“情景设置”。它是装配过程中简易、快速、静态的实验室仿真：以固定装配、位置和运动条件快速评估效果，不保证计算结果完全符合真实战斗。

界面说明：“按当前情景估算，供装配参考。”具体结果同时披露必要假设，不用泛化提示掩盖计算缺失。

首要问题是：

1. 传电后电容是否稳定，特别是两艘“大白”互相传电后，当前配置舰船能否持续工作。
2. 受到敌舰毁电、或传电与毁电同时存在时，当前配置舰船还能否稳定、能支撑多久。
3. 对不同目标，在不同距离和速度矢量下，实际应用 DPS 是多少。

“静态”指位置、速度与操作状态作为给定条件，不模拟完整战术过程；电容稳定性仍需要分析周期扣电、回充、传电与缺电反馈，不能仅凭平均收支给出保证。

## 与装配绑定的本地多情景

- 每个本地装配拥有独立的情景列表与当前选中情景。支持新建、命名、复制、保存、删除和快速切换。
- 情景设置区域顶部提供紧凑选择器及管理入口，例如“独立运行 / 双船互传 / 对巡洋舰近距离 / 对护卫舰高速”。名称可自定义。
- 提供“不应用情景”状态，查看装配自身指标。它不删除已保存情景。
- 情景修改先成为草稿，明确显示未保存；切换前可保存、放弃或取消切换，不能悄悄丢失修改。单纯选择情景不改变装备与技能配置。
- 保存情景与保存装配的动作和状态分开；选中项随本地装配记住。重开装配后恢复选择并重新计算，不冒用过期结果。
- 情景关联本地主装配身份。选择其他装配作为目标或友舰时，在情景内创建独立参与舰实例；同一装配可被多次选用，也可以创建与本舰相同配置的另一艘船。
- 参与舰引用装配及用于计算的修订。引用已更新时提示更新并重算；引用已删除时要求重新关联，不按空船或无限供电继续计算。
- 主装配正在编辑时使用当前工作版本；情景不覆盖主装配。一次计算冻结全部参与舰版本，期间修改使旧结果标记过期。
- 旧单一 scenario 数据迁移为“原有情景”，保持原条件，不默认改写已有装配或覆盖用户数据。

## 工作区就是情景结果视图

选择情景后，整个配置工作区统一显示当前情景下的数值，包括装备行、资源与右侧属性栏、悬停检查器和 DPS 函数图。情景设置只负责情景管理与条件配置，不建立独立数值结果面板，不重复展示 DPS、电容稳定性或双方结果。

- 以同一装配工作版本、同一技能及模块配置在“不应用情景”时的数值为对照基准。
- 数字降低显示红色，升高显示绿色，不变保持原色。颜色严格表示数值升降，不代表收益或好坏；耗电升高同样为绿色。提供可访问的升降说明，避免仅靠颜色识别。
- 比较须保持同一指标定义和单位。不可计算、缺少基准及纯文字状态不强行做大小比较，不以零回填；理论值与应用值的比较需明确其对应关系与计算条件。
- 当前情景名称在工作区保持可见，明确当前数值环境。切换情景同步更新全部视图；取消应用后恢复装配自身数值及正常颜色。
- 所有区域使用同一计算修订与情景上下文；计算中明确标记，避免部分区域仍是旧情景却显示为已完成。
- DPS 函数图显示当前情景的 X 坐标：距离模式为当前距离，信号半径模式为当前目标签名，角速度模式为当前角速度。用带坐标值的竖向参考线和曲线交点标记，并显示该点 DPS；Tab 切换后标记同步切换。
- 图内鼠标采样点与当前情景点分别显示，移动鼠标不覆盖或修改当前情景 X 坐标。
- 来源船的电容状态如为持续供电判断所需，可参与内部计算，但只展示当前配置舰船的结果。

## 情景设置内容

沿用现有局部平面与舰船操作方式扩展，不另造完整战斗实验室。

### 参与舰与位置、速度

- 本舰、目标、友舰分别显示名称、所用装配、技能方案、模块/推进状态。
- 可直接选取本地装配作为目标；目标信号半径、防御层和抗性等来自所选配置。覆盖值应明确标记，不能与原装配值混淆。
- 在平面中调整位置和速度箭头，同时提供距离、速度和方向的精确输入。
- 本舰与目标各自拥有速度矢量；界面派生显示相对速度、横向分量和角速度，并保持图形与数值一致。
- 区分炮塔使用的相对角速度与导弹应用所需的目标速度；不能用一个 speed 字段替代所有运动条件。
- 位置与速度为当前截面的固定条件，不暗中推进位置或宣称完成了追击、环绕、碰撞和完整交战仿真。

### 传电与电容稳定性

- 在参与舰之间建立有方向的传电连接，选择具体模块和目标；支持 A→B 与 B→A，同配置的两艘船仍是独立实例。
- 两艘“大白”互传是首轮验收样板。操作应当是选友舰装配、设置相互传电、确认双方开启模块和距离，然后在工作区电容属性中查看当前配置舰船的结果。
- 明确双方初始电量、开启模块、传电周期及距离条件；同一传电模块不得同时向多个目标无约束输出。
- 共同求解双方电容：传出方支付本舰消耗和传电费用，接收方仅在实际成功传电时取得收益；电量不足、射程不满足或停机的来源不能持续供电。
- 明确启动相位、同刻顺序和重试政策。单船稳定不代表双船闭环稳定，平均盈余不代表每个周期都能成功。
- 仅在当前配置舰船的电容属性区显示“稳定 / 将耗尽 / 观察时长内未耗尽但未确认稳定 / 条件不足”，并显示本舰稳定波动区间或预计耗尽时间。情景设置不另建电容结果面板，也不展示双方稳定性对照。
- 在当前配置舰船的电容检查器中可展开本舰电量曲线和首次关键失败：例如 B 缺电导致某次传电未发生，随后 A 电量下降。只有模型提供因果证据时才如此归因。
- 注电库存、外部毁电、距离失准等需要可见假设。尚未接入的机制明确标识，不能默认无限补给或隐藏缺失。
- 结果表述为“当前情景模型下稳定”，不作为实战承诺。

### 受到毁电

- 情景可添加一个或多个敌舰毁电来源，选择其装配、启用的毁电模块、作用目标及距离；与友方传电可同时配置并保存。
- 默认作用目标为当前配置舰船。情景设置只展示条件和连接，不增加独立毁电结果面板。
- 根据来源模块实际周期、毁电量、距离效果、本舰电容战抗性及剩余电量求解；超出作用条件或来源无法支付启动费用时，不继续凭空施加毁电。
- 本舰电容属性统一显示受毁电影响后的续航/稳定状态。检查器展开受到毁电的来源、周期、有效毁电量及必要条件；同一时间线同时计入自然回充、本舰耗电、传电和毁电，不用简单平均相减替代周期判断。
- 数值仍与同一装配无情景基准比较，降低红色、升高绿色；稳定等文字状态明确表达，不强行作数值升降比较。
- 来源缺失、未支持的毁电机制或输入不完整明确提示，不当作零毁电。只展示本舰结果，来源状态仅在解释供给或毁电中断的必要原因时出现。
- 首轮覆盖：单一毁电、多个来源、传电与毁电同时存在、距离变化、抗性变化、来源停机及本舰电量耗尽；情景与这些结果同样不随图片分享。

### 对目标 DPS

- 情景设置提供目标、距离、双方速度/方向及目标签名等条件；当前应用 DPS 由工作区原有攻击属性区显示，不另建情景 DPS 结果面板。检查器说明理论输出与应用输出的区别。
- 明确是否含换弹、目标抗性、无人机贡献与预热。目标防御层不同不应悄悄沿用同一个抗性结果。
- 快速切换保存情景即可比较不同目标或运动条件，不要求反复重填设置。
- 总 DPS 悬停检查器读取当前情景作为基准：Tab 循环“距离 / 目标信号半径 / 角速度”，标出当前情景点。
- 图像参数扫描是临时分析，不保存回情景；其余条件固定并可见。角速度扫描与用户设置的速度矢量对应关系必须说明，不混淆独立扫描与真实运动轨迹。
- 曲线标题明确应用 DPS，右侧原有理论 DPS 如保留则单独标识，避免把同一个名称用于两种口径。

## 图片分享边界

用户要求情景不随图片分享出去，包含可见图片和其中装配码两个层面：

- 分享数据使用允许字段清单，仅导出装配、允许的技能快照等原有分享内容，不包含情景列表、当前选择、草稿、目标/友舰引用、几何、连接关系或情景结果。
- 图片正文不显示情景名、目标、友舰、传电/毁电来源、情景图、针对目标 DPS 或互传后的电容稳定性。
- 分享前为同一装配工作版本单独计算“不应用情景”的报告，不能把当前情景增强后的结果去掉标签后仍画入图片。
- 此过程不切换用户当前情景，不改动已保存数据。中性报告不可用时显式提示，不回退使用情景报告。
- 从图片导入只生成装配，不恢复情景或引用他人的本地装配 ID。

## 现有实现与接入点

- app.js 当前以 fitRecord.scenario 保存一个情景，靶标设置入口需要改为情景选择与设置入口。
- linked_scenario.py 目前将外部传电模块转换为周期收入，并明确不递归求解来源关联；它不足以证明双方互传稳定。新情景计算应使用统一引擎的多实体电容模型，避免递归调用各舰已有情景。
- fit-binary.js 的分享编码当前未写 scenario，fit-image-code.js 导入将 scenario 清空，这个隔离应保留并扩展到多情景。
- share-image.js 当前把目标、应用 DPS、传电及毁电来源画到图片正文，必须移除该分享路径，并改用独立的无情景报告。
- 本地记录建议以 fitId 关联 scenarioId 列表和 activeScenarioId；情景拥有自己的版本、参与舰实例、装配绑定、连接与假设。具体存储格式在实施时确定，不复用可分享装配载荷作为情景存储边界。

## 验收

1. 同一装配保存至少三种情景，切换、重开、删除及未保存草稿处理正确；不同装配的情景不串用。
2. 两艘相同装配的“大白”互传，双方费用和收益分别计入；降低一方初始电量、关闭传电或移出范围后，另一方结果正确响应，不出现无限供电。
3. 改变目标、距离及双方速度方向时应用 DPS 同步更新；图形和数值一致，炮塔与导弹正确使用各自运动输入。
4. 总 DPS 检查器 Tab 切图不改变情景，不重置悬停锁定，当前标点与同一上下文结果一致。
5. 有情景与无情景时分享同一装配，输出均基于无情景计算；可见图片及二维码均不包含情景及本地引用，导入后没有情景。
6. 条件缺失、引用删除、版本更新、计算失败和异步旧响应不会生成假稳定、假零值或混合结果。

7. 选择情景后装备行、属性栏和检查器一致更新，升降颜色相对于同一装配无情景基准；取消情景后恢复。情景设置本身没有重复结果面板。
8. 三种 DPS 图均标出当前情景 X 坐标和对应 DPS；鼠标读取其他点时，当前情景标记仍保留。
