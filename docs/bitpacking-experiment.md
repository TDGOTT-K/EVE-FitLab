# 固定位宽装配编码实验

2026-09-13。实验文件 experiment-bitpacking.mjs；结果 output/bitpacking-comparison.json。只读本地装配库，不修改装配或生产编码器。

比较 9 份现有装配及 2 个合成的 20 槽、八位数 ID 场景。每种编码都解码并与现有 packFit/unpackFit 全字段结果断言一致。保留全部技能、文字和舱内物品，只替换槽位部分；比较原始和 gzip 两者中较小者。

方案：当前 LEB128；固定 27 位物品/弹药 ID；由本装配最大 ID 决定位宽；固定 27 位并以存在标志省略空物品/弹药；自适应位宽并省略空 ID。实验槽位块还包含 3 位槽型、10 位槽号和 3 位状态，不能把仅物品 ID 的 68 字节直接当成完整装配大小。实验数据另含分段长度、位宽和槽数头部。

9 份实际装配载荷总计依次为 4220、4454、4348、4257、4249 字节。当前编码总计最小。固定方案中最佳值不能被解读为普遍最优；这是本地样本和本次字段排列的结果。

刷洞pld：当前 517 字节；固定27位 561；自适应位宽 528；固定27位省略空ID 529；自适应省略空ID 531。共同的二维码封包另加39字节，因此当前仍是556字节、一张码。

巴戈龙样本：当前137，最佳固定方案119。20个不同八位ID合成场景：当前169，省略空ID方案148；20个重复八位ID：当前107，省略空ID方案136。重复程度会改变压缩效果。

决策：本次不更换生产编码、不新增图片格式；收益不足以证明值得增加兼容分支。保留实验脚本，可在更多真实装配上继续比较字段排列、装备字典或稀疏槽位编码。本次未生成安装包。
