# 右侧属性检查器升级设计

2026-09-17 · 第一版设计稿，基于现有 FitLab 工作台；尚未修改生产界面。

## 设计目标

鼠标停在一行属性上，玩家应当能快速知道：这个数值表示什么、主要由谁决定、当前条件下有什么限制。需要深入时，再看具体装备、技能和公式。

沿用现有深色青蓝主题、右侧属性行入口、物品图标及可继续追溯来源的能力。不同属性使用不同的信息主体，共享标题、条件、逐层悬停查看交互。

## 现状诊断

- explanations.js 把所有内容渲染为 terms/result/conditions，结果在底部，缺少摘要与分组。
- engine-view.js 的武器 DPS 首层只有“总输出减无人机输出”；齐射和锁定数量存在重复当前值的解释，无法帮助判断装配。
- attributeDetail 直接暴露倍率、执行序号、六位叠加系数；玩家需要自行翻译为实际收益。
- calculationDetail 将“待补环节”“尚未闭合”等内部诊断混入阅读主体，却没有直接说明哪些结果不可据此判断。
- 一些未被修改的属性没有检查器。基础状态仍需要说明含义和适用条件，不能以“数值没变”为由隐藏帮助。
- 保留现有约 800 ms 停留锁定、环绕反馈、下一层悬停及移出关闭机制，本次不改成点击固定。
- 当前来源不一定完整，不能仅靠改文案宣称已解释全部贡献；数值仍须来自实际引擎响应。

## 统一信息层级

### 第一层：悬停摘要

宽度建议 380–440 px，默认不超过约 400 px 高。优先向属性栏左侧展开，避让当前行并夹在窗口内。

1. 顶部：属性名称、当前值、单位。当前值只作一个明确的视觉主值。
2. 一句解释：说明口径或直接有用的结论，例如“当前开启模块的平均耗电”。不能没有对照就称“足够”“优秀”“稳定”。
3. 主体：按属性展示贡献条、收支、分层构成或条件下的效果；默认最多五个主要项，可展开其余项。
4. 紧邻相关数值的条件：例如“均匀来伤”“不含换弹”“目标未选择”。影响解读的条件不能藏在最底层。
5. 底部：来源与计算的逐层悬停入口。技术诊断不占据首屏。

不默认出现“Dogma”“引擎输出”“各项相加”“执行序号”；名称、单位、精度必须统一。空来源不回填“贡献项 0”。

### 第二层：逐层悬停详情

沿用现有停留锁定后悬停来源项进入下一层的机制，包括层级关系、移出关闭与 Esc 逐层关闭。不增加点击属性行、固定按钮、侧面板或面包屑导航。

详情重点改造内容与布局，保留现有工作台列宽。DPS 图像需要的面板宽度建议为 440–520 px，实际尺寸在原型中验证。

### 第三层：公式与来源

公式使用可读分式、括号和求和排版。每个变量常态有可交互下划线，悬停或键盘聚焦显示含义、当前值、单位；继续悬停可查看下一级来源。

来源按舰船基础、技能、装备、状态/环境分组；需要时查看实际求值顺序、规则及数据版本。数学乘法链不得伪装为可加总的独立贡献。

## 各类属性应回答的问题

| 属性 | 玩家要知道什么 | 默认主体 | 深入内容与约束 |
| --- | --- | --- | --- |
| CPU / 能量栅格 / 校准 | 谁占用最多，还能装什么规模的装备？ | 已用、总量、剩余；按装备分组的占用条；超限差额 | 容量来源、技能节省、单件占用；不在缺少兼容性判断时推荐具体装备 |
| 总 DPS | 距离、目标签名和角速度如何影响输出，谁贡献了多少？ | DPS 函数图；Tab 循环切换距离、目标信号半径、角速度；简要武器/无人机贡献 | 明确曲线固定条件与应用口径，来源继续悬停展开；备用无人机不计入当前总值 |
| 武器 DPS | 哪一组武器贡献多少，为什么？ | 装备图标与名称、弹药、数量、组 DPS；齐射与周期 | 每件差异、伤害与射速来源；状态、弹药、变异或有效参数不同不得合并 |
| 无人机 DPS | 哪些无人机在输出？ | 已出动数量/可控数量，各组贡献；备用不计入的提示 | 伤害、周期、技能；实际应用必须另说明追击、距离等条件 |
| 含换弹 DPS | 换弹损失了多少？ | 不含换弹 → 含换弹，绝对和百分比损失；逐武器组弹仓、周期、换弹时长 | 公式口径及弹药机制；不以理论 DPS 为下限回填；无损失与未计算分开 |
| 对目标 DPS | 为什么打不满？ | 当前目标、距离、运动/签名条件，理论与应用值 | 按武器机制解释跟踪、射程、爆炸应用、抗性；不能将相互作用硬拆成可相加的损失 |
| 齐射伤害 | 一轮打多少，伤害类型是什么？ | 武器分组与四种伤害构成 | 明确是否含无人机、是否抗性前；异步攻击不能冒称同刻命中 |
| HP / EHP | 哪一层扛伤，取决于什么来伤？ | 三层贡献条；选中层的 HP、EHP 与当前来伤比例 | 各层计算；EHP 不包含维修和自然回充，完全免疫不显示为 0 |
| 单项抗性 | 该伤害实际穿透多少，多装一件收益是否衰减？ | 抗性与剩余伤害率；基础及主要有效来源 | 叠加前后加成、叠加顺位；抗性变动用百分点，不能把剩余伤害倍率与抗性百分比相加 |
| 主动维修 | 每次修多少、多久一次、耗多少电？ | 模块分组、单轮修量、周期、HP/s、耗电；EHP 模式明确来伤 | 区分理论持续开启与模拟中实际成功周期；缺电、过量维修、辅助限制依赖真实结果 |
| 被动回盾 | 当前回多少，峰值何时出现？ | 当前与峰值、护盾比例；有真实输入时显示回充曲线 | 满盾回充为零；没有当前护盾条件时只展示峰值，不虚构当前值 |
| 电容量 / 回充时间 | 哪些装备或技能改变了电容？ | 基础与当前，主要容量/回充时间来源 | 回充时间是游戏参数，不能描述为恰好充满所需时间 |
| 耗电 / 净耗电 | 最大负担是谁，收益来自哪里？ | 模块支出、注电/吸电/外援收入分列；主要耗电模块占比 | 明确净耗电是否含自然回充；吸电和外援条件，不混入无来源的保证收益 |
| 电容续航 | 能维持多久，为什么会断电？ | 明确初始状态与运行条件；稳定区间或耗尽时刻；主要支出 | 平均模型平衡与离散模拟续航分开；曲线来自实际样本，未达结论显示观察时长 |
| 最大速度 | 哪些状态决定速度？ | 推进状态、当前上限、主要增速/减速来源 | 最大速度与当前速度分开；不能据静态上限声称已达到该速度 |
| 起跳时间 | 从什么状态开始，需要满足什么？ | 静止起步到 75% 速度的估计；质量与惯性 | 与实际入跃分开，说明朝向、扰断等条件；不随意向上取整成服务器 tick |
| 信号半径 | 为什么变大/变小，会影响什么？ | 基础与当前；推进和其他主要来源 | 与锁定时间及武器应用的关系；没有攻击者参数时不报受伤倍率 |
| 锁定距离 / 数量 | 哪个限制在起作用？ | 有效上限及已知瓶颈：舰船、技能、效果 | 缺少限制来源时不推断；锁定数量不等于可同时开火目标数 |
| 扫描分辨率 | 锁定当前目标要多久？ | 已有目标及引擎支持时显示锁定时间，否则解释与目标签名的关系 | 来源与公式；缺少目标时不默认一艘虚构靶舰 |
| 感应强度 | 哪些来源提高抗干扰能力？ | 当前种族强度和来源 | 有明确 ECM 来源及条件时才显示概率；不同 ECM/破锁机制不能混用 |
| 无人机控制距离 / 数量 | 最远能指挥多远，数量被什么限制？ | 有效范围/数量和来源；与机库、带宽分别呈现 | 范围不冒称武器射程；越界行为按引擎实际政策说明 |
| 对外效果 / 采集 | 单次效果和实际生效率是多少？ | 单次、周期、作用距离或采集量 | 对目标抗性/距离、往返及卸货是否计入明确展示 |

## 三个首轮样板

以下数字仅用于说明排版，不是已接入引擎的结果。

### A. 总 DPS

```text
总 DPS                                      323.1
当前启用武器与已出动无人机 · 不含换弹与命中损失

舰载武器                         251.1   77.7%
  [武器名称] ×3 · [弹药名称]       251.1
无人机                            72.0   22.3%
  Hobgoblin II ×[实际数量]          72.0

伤害构成                 电磁 / 热能 / 动能 / 爆炸
[距离]    目标信号半径    角速度        Tab 切换
             DPS 函数图像
固定条件：[目标签名] [角速度/速度] [抗性口径]
当前情景目标位置与对应 DPS 在图上标点
停留锁定后，继续悬停查看来源
```

每个条目都有对象身份；实际名称和数量来自引擎，缺失时明确无法展开。不显示三个没有名称的“DPS 83.70043”。

### B. 护盾电磁抗性

```text
护盾 · 电磁抗性                              60.0%
每 100 点电磁伤害有 40 点穿透抗性

基础抗性                                    20.0%
有效来源                           [装备/技能名称]
来源与计算：20% 基础 → 剩余伤害 ×0.5 → 60% 抗性

仅描述抗性折算；不含维修或其他伤害应用修正
```

来源顺序和 0.5 倍率须来自实际轨迹。不要写“装备提供 +40% 抗性”，因为它混淆了倍率与百分点。

### C. 电容续航

优先呈现结论、初始电量、开启模块、是否含注电/外援和计算模型。下方用收入/支出两组列出最大影响项，再展开曲线与具体事件。平均收支尚有余量但存在大额周期扣电时，不能只显示绿色“稳定”。

不在没有独立对照运行时声称“关闭这件装备就能稳定”；可提供后续“预览停用”动作，由引擎重新计算，预览不改变保存装配。

## 与情景设置的关系

原“靶标”入口改名为“情景设置”。情景与本地装配绑定，支持保存多个并快速切换；不随图片及装配码分享。它是简易、快速的静态参考仿真，重点覆盖传电、受到毁电及两者同时存在时当前配置舰船的电容稳定性、不同目标/距离/速度矢量下的 DPS。完整规则见 [情景设置设计](scenario-settings-design.md)。整个配置工作区作为情景结果视图，情景设置本身不设独立数值面板。数值相对于同一装配无情景基准降低变红、升高变绿、不变保持原色，颜色仅表示升降。只展示当前配置舰船的结果。DPS 图像以当前情景为基准，标出当前模式对应的 X 坐标、竖线和曲线交点及 DPS；临时扫描不修改情景，鼠标读点不替换当前情景标记。分享须独立计算无情景结果。

## 总 DPS 函数图与 Tab 切换

用户明确要求：DPS 悬停面板直接显示函数图像，按 Tab 键在以下三种模式间循环，不需要点击或先固定面板。

**DPS 随距离 → DPS 随目标信号半径 → DPS 随角速度 → DPS 随距离。**

- 首次默认距离模式；同一工作台会话内记住上次模式。切换只更新图像、横轴及条件说明，不关闭面板、不重启停留锁定动画、不改装配或情景目标配置。
- 图上方常驻三个模式名称，高亮当前项，旁边显示“Tab 切换”。这些是状态提示，不要求用户点击。
- 纵轴为 DPS；横轴依次是距离（km）、目标信号半径（m）、角速度（rad/s）。主曲线是所声明范围内的总应用 DPS；主值的理论口径与曲线应用口径分别标明。
- 当前情景目标条件对应的位置用标点和参考线标识。锁定后移入图内可沿横轴查看采样点坐标和 DPS；不因移动十字线改写当前情景目标。
- 图下显示固定条件：距离、目标签名、角速度、目标速度、抗性口径、换弹与无人机口径中与当前模式相关的项目。只扫描横轴变量，其余独立输入固定，不暗中联动。
- 距离扫描默认固定角速度；不默认为固定横向速度。角速度扫描需明确几何假设，不把角速度直接替代导弹公式所需的目标速度；如无法构成有效条件组合，标明限制而不生成伪曲线。
- 不受扫描变量影响的贡献可以为水平线。例如导弹不会仅因炮塔角速度参数改变就凭空衰减。无人机的应用需要自身几何/运动条件；缺少支持时明确总曲线不完整，不能悄悄拿母舰几何替代。
- 目标抗性前后、不含/包含换弹、无人机连续输出或实际追击等口径在三个模式间保持一致。缺少条件时图位说明需设置什么，不绘制猜测数值；合理默认条件必须可见。
- 横轴范围由有效机制范围和当前条件确定，保证当前点可见；三个模式保留各自范围。纵轴从零开始，同一条件下切换时尽量使用一致量程，避免自动缩放掩盖损失。
- 射程门槛与其他不连续处保持断点或阶跃，不使用平滑插值伪造过渡。未支持区间留空并标注，不能当作零 DPS。
- 按 Tab 的行为仅在 DPS 检查器处于当前悬停链、焦点不在输入框/可编辑内容且未使用组合修饰键时生效。离开后恢复普通 Tab 导航；不全局截获。提供方向键可选模式的键盘可达入口，确保可以退出该区域而不形成焦点陷阱。
- 快速连续切换时按当前模式与修订匹配响应，旧请求不能覆盖新曲线。加载/失败保留模式提示；缓存键包含装配修订、目标条件、计算口径、横轴范围和规则版本。
- 曲线采样来自引擎的真实应用计算或明确声明的实验，不在 UI 写第二套伤害公式。标出未接入状态，不用示意曲线冒充真实数值。

## 交互规则

- 保留现有悬停显示、停留锁定、环绕反馈、来源逐层悬停及移出关闭机制。此次升级不增加点击固定。
- Esc 继续逐层关闭；键盘焦点入口保留。Tab 曲线切换的作用域只限上述 DPS 场景。
- 切换曲线不改变已有检查器链的锁定状态或位置。图像在预留空间内更新，避免面板跳动。
- 计算中标识旧结果，失败不将旧值冒充新结果；装配修订更新时不混合旧来源与新曲线。
- 基础数值没有加成时照样可查看含义与条件；不强制制造空的来源列表。
- 差量必须标明基线（保存版本/上一修改/当前预览），不混用。颜色表示方向之外，还需知道该指标是越大越好还是取决于场景。
- 减少运动偏好下取消装饰动画；所有贡献和警告不只靠颜色区分。

## 数据与接入

将现有通用解释对象逐步换成有属性类型的展示模型。建议字段：metricId、kind、label、value、unit、scope、conditions、breakdown、sources、formula、coverage、revision。此为 UI 适配模型，不要求 N 号引擎采用同名字段。

- breakdown 必须保留对象实例、装备/弹药、状态与数量；只有有效参数相同才合组。
- 数值可用性和解释完整性分开：可以是“数值可用，部分来源未提供”，也可以是“该数值不可计算”。不能统称计算失败。
- complete/partial/unavailable 是展示约定，由适配器依据实际覆盖信息映射；无证据不自行推断 complete。
- 没有来源时说明“当前可查看总值，暂未提供装备分项”，不是“无装备贡献”。缺失不是零。
- 主值、分项、公式、条件必须对应同一修订和计算上下文，防止异步晚到响应混合。
- 主值与分项相差仅由显示舍入引起时作舍入说明；实质不一致必须显式处理，不能隐藏差额。
- 单位换算与显示舍入可在适配层做；伤害应用、EHP、叠加、回充、反事实收益等由引擎统一提供，避免旧前端/Python 计算污染 N 号结果。
- UI 不调用原始文件检查点，也不直接拼接任意技术日志作为玩家解释。技术诊断进入可展开的详细记录。

## 实施顺序与验收

1. 在现有工作台旁建立检查器设计样板，先验证总 DPS、单项抗性、电容续航三类。演示数据明确标识。
2. 保留共用悬停交互，改造内容布局与有类型的展示模型，再接资源、输出、防御、电容；原有调用者逐步适配，避免一刀切文案替换。
3. 覆盖机动、锁定、感应、无人机与对外效果；随后对接 N 号真实来源和模拟数据。
