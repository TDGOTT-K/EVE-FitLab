# N 号引擎 0.180 / r23：静态装配 UI 接入缺口清单

日期：2026-09-18。视角：现有 FitLab 的 UI 与宿主适配开发。仅审查独立交付副本 `D:/AI/GPT6/N号引擎-UI接入-0.180-r23`，引擎功能提交 `9dc0e6f`、交付提交 `f2e57dc`、SDE 3503375、静态规则 v49。

**结论：这份副本具备很多真实静态计算和编辑能力，但还不能直接替换现有装配工作台的全部计算体验。最大阻塞是无关技能导致整份分析失败；其次是静态情景/应用曲线缺少统一公开入口、目录与可计算范围脱节，以及攻击汇总口径不能直接满足 UI 开关语义。**

本清单不包含虚拟战斗沙盒、脚本编辑、策略、任务调度、实时战斗、回放、检查点控制或跨星系仿真 UI。情景设置仍是本地装配的快速参考工具，不扩展为战斗实验室。本轮只做阅读、只读查询和文档登记，没有改引擎源码或产品代码，没有修改用户装配。

## 证据和判断标准

- 已核对 START-HERE、UI-BASELINE、交接文档、r23 工具 Schema、MCP discovery、静态分析/编辑/目录源代码、相关 CLI 入口，以及 FitLab 首测 F001–F029 与当前适配代码。
- 当前 MCP 为 23 工具。静态 `fit_analyze.context` 只有 incomingDamage、capacitorFraction、shieldFraction；incomingDamage 是本舰承受伤害的比例，用于防御，**不是目标抗性或攻击应用情景**。
- 真实只读查询证据：[static-ui-r23-probes.json](evidence/static-ui-r23-probes.json)。查询没有启动战斗任务。
- “实测”表示本副本本次返回；“代码/契约确认”不冒充本轮完整数值回归；“建议接口”不是已经存在的 API 名称。
- 接收未训练数值探针不等于合法配装认证：舰载机遍历采用空技能、单成员、未部署，以隔离型号准入；允许存在 SKILL_REQUIRED，分别记录覆盖与准入结果。

优先级按本次迁移排序：P0 是接入阻塞，P1 是核心装配体验，P2 是补齐项，不替代原故障台账的严重程度定义。

**缺 MCP 工具并不意味着必须修改 N 源码才能继续。** 对已存在的 Core/CLI 能力，可以评估在 FitLab 增加独立的薄宿主/受控 CLI 桥接，锁定该副本并验证输入输出、批量性能和错误语义。此路线仍使用同一引擎公式；它与在前端另算物理规则不同。E01 等真实覆盖问题则不能靠封装解决。

### E01 的确切复现边界

触发的 10 个技能：3322、20210、20211、20212、20213、25718、37796、37797、37798、37799。分别涉及 660/661/662/668、1851、6396/6679/6400/6401 等效果。

在临时请求中移除这 10 项后覆盖恢复，用于定位因果；**这不是推荐修复方案，未改用户角色。** 单个无关技能 3322 的反例足以说明问题不只在“505 项太多”。目前全或无返回是源码中刻意的可信度保护，修复应先判断相关性，不能简单删掉保护并返回看似可信的部分数值。

### E02 的型号抽查边界

MCP published 目录返回 94 条舰载机记录（本页无后续游标），65 条被静态主攻击准入拒绝。当前 FitLab 筛过级别/中队规模后显示 53 条，其中 24 条拒绝。拒绝的实际 UI 示例有修道士 I、圣甲虫 I、塞壬 I、德洛米 I，以及骑士 I/II、蚱蜢 I/II、萨梯 I/II、格拉墨 I/II。完整名单见证据 JSON。

不能把“轻型/重型”粗分类当成能力保证；同类下不同主攻击家族仍可能拒绝。没有遍历所有装备、所有技能、所有脑插/药剂家族，因此不外推任何全目录支持率。

## C. 尚需约定口径，不能直接判为引擎 bug

1. **无情景曲线参考目标**：按用户确定的 S/M/L/更大武器对应护卫/巡洋/战列/无畏。具体参考目标参数和其余变量的理想条件必须固定、可见；这属于静态查询条件，不可暗中把目标抗性混进 DPS。
2. **装载、部署、攻击选择分开**：原生 fighter.deployed 同时参与部署管数/分类资源和主攻击汇总；UI 的“在某个发射管里”“待命”“只关某种武器”不是同一件事。当前武器排除存 UI 字段，原生请求不变；后续若要正式跨客户端复现所选总值，需要补静态选择上下文/聚合契约，而不是冒用 deployed=false 腾管。
3. **部分数值如何展示**：可以保留静态元数据、用户输入和已证明不受影响的分项；但未知影响路径不能由 UI 猜测安全。引擎返回“未支持”和“确为零”必须分开。
4. **晶体和火箭的持续值**：有限弹量、有弹期间周期输出、含普通换弹的长时平均、一次性牺牲各是不同口径。现有 coldSustainedDps 不自动等于有限库存下某时间窗口的实际输出。
5. **属性绿/红方向**：不能把一律变大视为更好，CPU 占用、信号半径和修复耗时等需要方向定义；SDE highIsGood、使用量/剩余量语义和用户指定的情景比较基准须一致。主要由 UI 的指标定义处理，不重写数值公式。
6. **新旧存档**：旧原生规则绑定明确拒绝跨版直接读，不等于缺少保存能力。保留原文，以当前版本重新验证原始输入再建立新绑定；UI 无权改版本号绕过。现有 FitLab 自存文档需保留其 UI 字段，新接口不能默默丢弃。

## 建议的执行顺序

1. **先修 E01**：否则角色选择最常见的“全技能 V”会阻断几乎所有后续验收。补同角色在不同武器家族上的适用性回归。
2. **E02 能力发现 + U07 错误呈现并行推进**：立即避免反复出现“目录可选，装入才报看不懂的错”。没有数据时不做假支持标签。
3. **定义并补齐 E03/E04/E05 的静态查询契约**：恢复用户已经设计过的情景、曲线、DPS/EDPS 和本舰电容，完全不需要沙盒 UI。
4. **接 U01/U02 深渊真实生成，同时推进 U03 事务链**：已有能力先消费，不再用 mock 代替；深渊 UI 按用户要求做二次设计和逐项验收。
5. **补 E06/E07/E08 与 E09**：扩大真实装备家族、特殊攻击分项、库存和独立服药体验。
6. 最后统一 U04–U10 的目录、说明、分享、性能及 Windows 验收。防御不另开重设计项目，只核对绑定、口径与原布局。

交给引擎负责人的核心请求可以浓缩为：**让常用全技能配装可算；提供真实能力发现；把已有 Core/CLI 静态应用、外部电容与药剂查询以稳定接口给 UI；补齐输出选择/特殊分项/静态库存的明确契约。不要为这批需求新增脚本沙盒 UI。**

## 源码核对定位（相对副本根目录）

- `src/NEngine.Mcp/FittingTools.cs`：23 工具中静态工具的实际公开面；错误 envelope。
- `src/NEngine.Core/Dogma/EveFitting.cs`：EveFitRequest / Analysis、coverage 提前返回、武器投影与汇总、普通无人机准入。
- `src/NEngine.Core/Dogma/ShipMetrics.cs`：EveMetricContext、平均电容与防御模型。
- `src/NEngine.Core/Dogma/EveEditor.cs`：事务、预览差量、可提交规则、导入导出。
- `src/NEngine.Core/Data/EveCatalog.cs`：目录元数据、traits、变体、无 gameplay coverage 保证。
- `src/NEngine.Cli/Program.cs`、`SdeCommands.cs`：炮台/导弹、火箭、电子战、维修、服药等静态 CLI 出口。
- `src/NEngine.Core/Data/EveFighterPrimary.cs`、`Dogma/EveFighters.cs`、`EveFighterRockets.cs`、`EveFighterBombs.cs`：型号准入、主武器、分类额度、火箭周期输出与炸弹载荷边界。
- `src/NEngine.Core/Dogma/EveBoosterConsumption.cs`：独立副作用抽样及完整配装准入条件。
- `src/NEngine.Core/Dogma/EveReload.cs`：满弹仓/无限备弹假设。
- `src/NEngine.Core/Fitting/Contracts.cs`、`Dogma/DogmaGraph.cs`：FitIssue 与 DogmaTrace。
- `docs/mutation-generation.md`、`docs/catalog.md`、`docs/fitting-library.md`：已经存在而不应重复列为缺失的能力。

验收限制：未做全装备扫描、全部脑插套装或全部药剂的逐项认证；未跑引擎全量测试；未执行任何战斗任务。历史 UI-ready/全量通过记录不能替代本次实际用户场景复核。
