# 完整装配文件：能力验证入口

格式 `fitlab-static-fit-1`，扩展名 `.fitlab.json`。保持当前 0.190.8-ui.1/r41 引擎及游戏机制不变。

## 临时入口

- 装配库条目右键：导出完整装配文件。
- 装配库底部空白区域右键：导入完整装配文件。
- 选择文件后自动核对来源和重放结果；成功后点击导入为新装配。不覆盖已有装配。

这是能力验证入口，最终 UI 由用户重新设计和验收；没有把此功能当成发布批准。

## 保存与重放语义

本地装配库 ID 和原生 `nativeFitId` 分离。导入可以产生新 UUID，而原生输入身份、fitHash 和分析结果仍相同；原生会话仍独立，编辑、撤销及保存继续使用现有事务。

文件保存白名单 UI 输入，包括名称/标签/备注、技能、槽位/状态/弹量、晶体、无人机/舰载机、脑插/药剂选择、模式、输出口径、防御条件及观察窗口。不会携带原本的保存请求、原生会话引用或本地方案库管理指针。

情景的目标、传电、毁电引用保存为独立快照，包括未选中的预设引用；不会将这些来源导入用户装配库，也不会依赖接收端同名/同 ID 装配。快照优先于接收端本地来源。情景设置下拉可看到随文件带入的来源；工作台的计算范围说明明确提示冻结语义。

估价携带当次选定类型的原始报价快照及来源。导入后使用历史报价，缺报价仍缺失，不更新为当前价格；新增物品没有对应历史价格时继续明确缺项。

`replay.analysis` 是公开 fit_analyze 的完整 fit/context、fitHash 和结果摘要；`replay.capacitor` 是 capacitor_scenario 请求与结果状态/摘要/诊断；`replay.valuation` 是 fit_valuation 请求和结果摘要。可提取请求分别通过公开 MCP 或 CLI 重放，UI 不计算游戏数值。

导入先验证来源、结构和内容摘要，再复算完整原生分析、电容及估价并核对。失败不写库。JSON 整数与浮点整数（如 1 / 1.0）的文本差异不视为损坏；其他未知值不补零。内容摘要用于完整性核对，不是作者身份签名。

- 16 项相关 Python 回归、原生分享及编辑历史回归通过；随后新增多对象组合专项、来源缺失断言及对应重跑。62 模块静态检查通过。

## 未关闭的边界

- 当前原生分析直接抛错的装备仍不能生成完整重放文件，这是已交引擎的 P0 路径；本功能不伪造其结果。
- 未认证所有装备组合。实例在后续拖动/重排时的稳定身份仍需专项收口，不把一次往返相等外推成全部编辑生命周期完整。
- 导出体积超过限制明确失败，不截断；没有引入自动历史迁移或跨版本重新计算。
- 文件内快照的主动更新/解除冻结交互留给后续 UI 整理；当前保存、重新导出及计算均明确使用这些快照。
- 未重新打包 Windows、未发布，仍须用户主导最终 UI 重构和验收。
