### ENG-44-06：舰载机管位状态丢失及装载配额

**已确认的技术缺口：**r44静态EveFitFighter只有Id、TypeId、MemberIds、Deployed。无法表达管位编号、管内待命与备用机库。EveFighters.AddResources仅使用Deployed=true统计fighterTubes及fighterClass.*。UI有tubes/reserve和active两层状态，但原生转换后管内待命与备用均为deployed=false。

证据：

- 引擎src/NEngine.Core/Dogma/EveFighters.cs：EveFitFighter声明及AddResources。
- UI nengine_adapter.py native_fit：deployed = location == 'tubes' and active。
- 实跑native_fit对照：同一稳定身份中队分别放入tubes且active=false、reserve且active=false，生成的完整原生请求相等。此对照证明表达能力缺口，不是游戏规则的外部证明。
- 用户反馈：分类数量超额不能预装进发射管，只能少装不能多装。官方Fighter Controls确认装入和发射是分开操作，但没有明确写出分类超额预装限制：https://support.eveonline.com/hc/en-us/articles/207659599-Fighter-Controls 。维护任务需核实该规则；不要把聊天反馈或现有引擎实现本身当成官方规则证明。

影响：将中队设为待命会释放原生分类计数，可能允许UI在管内保存超过分类上限的中队。将所有管内中队强行传deployed=true会把待命贡献混入部署输出，不能作为修复。

所需交付：

1. 在公开静态输入/持久化/编辑接口中区分备用、已装管待命、部署及稳定管位身份；复用已有机制，若需新增游戏机制先提交边界方案。
2. 依据核实后的规则分别返回装载与部署配额、容量、合法性诊断及来源；确认分类上限为0的类型限制，不能只校验总管数。
3. 待命不计部署输出；备用不占管位，但占机库体积。显式输出预选不能改变位置或部署状态。
4. 验证：分类上限3、总管位4时，3管同类中队加第4管；其中一队切待命；同一队移到备用；类上限0；重复管位；总管位超限；保存/恢复。分别核对装载合法性与输出选集。
5. 提供同输入MCP/CLI回执、契约版本及兼容边界。UI在新契约交付后接位置字段和管内计数；当前未私自在UI增加独有配额规则，也未修改引擎。

### ENG-44-02：晶体换弹参考口径

**已确认现象：**当前工作台中“超级脉冲激光器II + 萨沙爱国者多频晶体L”的名义DPS、四类伤害、晶体实体和耐久可读，但含换弹行不可用，原生原因为`INSTALLED_CRYSTAL_NOT_CONSUMABLE_MAGAZINE`。

源码依据：`EveCrystals.cs`的`TakesDamage/FixedRuntimeSupported`；`OutputContributions.Build.cs`的`reloadCycleDps`缺项；`EveFitAnalysis.ColdSustainedDps`已有固定晶体支持边界。UI没有将名义值擅自回填为换弹值。

需要交付：

1. 说明哪些晶体可在既有静态能力下给出“固定已装晶体、不推进磨损”的参考输出；哪些必须有替换/磨损策略。区分参考循环DPS、有限实例输出和实际战斗平均。
2. 若既有能力允许，提供显式政策输入或明确命名的公开结果，复用现有投影；若不允许，给出缺失能力及最小条件，**不要为本单开发晶体战斗时序**。
3. 分别验证普通无损晶体、势力、T2、已声明耐久、缺失实例、耗尽实例，与普通消耗弹仓混装及含无人机的选集合计。
4. 返回实例身份、政策、适用范围、未计入项和来源。条件不足时不强行给完整合计。

复现起点：副本`examples/static-inventory/crystal-fit.json`；现象中的型号需从当前SDE目录解析并固定typeId，保存最终原生fit/context与回执。该示例是构造起点，不声称它就是上述UI现象的完整复现文件。

### ENG-44-03：审核新汇总契约，不重写机制

- 覆盖nominal/applied/effective/loaded口径、目标免疫、零命中、空选集、显式选择备用实体、部分静态依赖缺失。
- 覆盖炮台、导弹、智能炸弹、无人机、舰载机主武器及有限次数副武器；不能以单一标量倍率掩盖不同口径或使用策略。
- 审核`inspector.reloadDps`从现有换弹投影及目标比较结果组合的适用范围；超出范围必须不可用，不能盲目扩大声明。
- 对多维修器、离线/停用、远修、来伤免疫和特殊维修家族，明确哪些是已支持完整合计，哪些只能给分项。当前staticCoverage不完整时采用保守不可用；如细化需有依赖证据。
- 任何UI要展示的分项、选集合计、差量、比例和曲线，都要有公开查询结果或契约明确允许、可公开重放的展示组合。先提交指标对照表，再确定是否需补接口。

### ENG-44-05：采集先做能力答复

r43修复了未覆盖主动效果下的静态诊断保留，**不能据此声称已实现采矿运行时或所有采集率投影**。

检查已有原生属性/投影能否提供模块与无人机的单周期采集量、周期及静态参考率，列出所需目标/晶体/技能条件。按普通矿枪、露天采矿、气云、冰矿和采矿无人机分别给状态。仅缺公开投影可封装现有机制；缺机制就说明，不在本单实现矿石枯竭、航行、装卸或战斗调度。UI侧不写“采集量÷周期”独有业务公式。

## 不要交给引擎重复开发的项目

- 智能炸弹漏入武器小计/齐射：UI分类接线已修复。
- 电容首次供电不足时间：原生已有，UI已自动延长查询至最多3600秒并显示真实事件时间。平均稳定、首次付款失败和电容归零不是同一概念；未查到终点不能冒充稳定或耗尽。
- 普通伤害条、维修行、悬浮面板、布局：由UI任务维护，沿用旧版设计；确需新UI须用户确认。
- LOCAL-001～008：r43已合入并复验，不是仍需全量重放的清单。
- 冻结旧分享来源的兼容迁移、战斗沙盒、发布打包：不在本轮引擎工作范围。
