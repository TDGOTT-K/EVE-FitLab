# 舰船对战实验室：世界、脚本与实验契约

状态：V2 设计草案，不是已实现 API。目标是让玩家编写舰船/小队策略、运行可复现实验、观察事件并改进策略，形成 EVE 版 Screeps 的体验。

v0.2 补充：[特殊机制与影响分析](mechanics.md) 定义范围、飞行物、预热、次级攻击、模式及作战单位的行为扩展契约。

## 1. 实验单位

世界支持多个阵营、控制者和实体，而非固定 attacker/defender。首批验证 1v1 与小队，不把持久 MMO 世界、服务器集群、完整新伊甸经济加入本次范围。

实体按能力组合：舰船、普通无人机、铁骑编队、导弹/其他飞行物、可作用目标与环境。拥有位置并不意味着拥有同一类运动、锁定或攻击行为。

每艘舰船具有 3D 位置、速度向量、朝向/导航状态、几何半径、签名、逐层 HP、电容、热量、锁定集合、模块状态、舱内资源和活动效果。目标绝对速度、相对速度、相对角速度是不同的派生量；玩家在平面视图操作，也不将底层坐标压成“距离 + 相对速度”两个标量。

运动命令包括定向航行、停止、接近、保持距离、环绕。保持距离/环绕是导航控制器的期望目标，不是瞬移到指定半径；实际加速、转向和惯性由运动系统处理。碰撞与导弹飞行模型有独立版本和支持等级。

## 2. 时间和结算

提案：控制者每 1 个模拟秒决策一次，世界内部使用整数微秒时间戳与事件队列。该间隔是 `lab-v1` 的可版本化参数，不宣称完全复制 EVE 服务器内部实现。动画帧率和宿主速度不决定战斗时钟。

事件队列按时间、明确的规则阶段和稳定序号调度；同阶段伤害从相同前置状态求值后批量提交，允许同时毁灭，不按“先遍历攻击者”决定胜负。

建议的边界顺序：

1. 将连续状态推进至事件时刻：运动、自然回充等；积分方法与最大步长固定在 profile。
2. 处理已经发生动作的到期事件：飞行物抵达、锁定完成、周期结束、远程传电到达、效果到期等。不同子类的排序策略版本化，不能由容器遍历顺序决定。
3. 对同阶段结算统一应用结果并处理毁灭/失效。维修在周期开始还是结束由能力规则定义；当伤害、维修、毁灭同刻冲突时必须有专门金样，未核准前标为实验规则。
4. 若是决策边界，为全部控制者发布同一已提交世界版本的观察快照。
5. 收集全部控制者的意图与手动命令。并发 worker 只加快收集，完成先后不影响优先级。
6. 按观察版本、权限、目标/锁定和状态校验；在同一前置版本上预留 CPU 无关的运行资源，如电容、弹药、能力次数。单舰竞争资源按显式激活优先级解决，不以消息到达顺序决定。
7. 原子提交有效意图及资源支出，生成即时效果与未来事件。所有即时效果按规则阶段成批处理，设置微步骤上限，避免零耗时无限事件链。
8. 发布结果收据、事件、世界哈希；需要检查点时在这里保存。

既有传电到期与本轮刚发出的传电是不同事件；后者不能倒灌帮助本轮已经失败的资源预留。电容状态和维修统计消费同一份结算，不允许各自选择先收入或先付出。具体与 EVE 的兼容顺序属于需要验证的机制清单。

模块运行状态至少区分离线、在线空闲、启动中、周期中、等待目标、换弹、重激活等待、停机待周期结束、过热/损毁；状态由能力定义约束。`Deactivate` 是否完成当前周期由规则决定，不默认为立即撤销已发射弹药。

## 3. 意图与收据

GUI 手动操作、内置导航策略、JS 策略最终提交相同的 BattleIntent；应用层管理命令（保存/删除文件、导入类型、创建实验）不属于战斗意图。

| 意图族 | 示例 | 核心校验 |
| --- | --- | --- |
| 导航 | `Navigate`、`Stop`、`Approach`、`KeepRange`、`Orbit` | 所有权、目标可见性、导航可用、参数范围 |
| 锁定 | `LockTarget`、`UnlockTarget` | 可见、锁定数、距离、电子战、时间 |
| 模块 | `ActivateModule`、`DeactivateModule`、`SetOverheat` | 模块身份/状态、目标条件、资源、超载支持 |
| 装填 | `ReloadModule`、`ChangeCharge` | 兼容性、货舱数量、状态、每轮消耗 |
| 无人机 | `LaunchDrones`、`RecallDrones`、`AssignDroneTarget` | 容量、带宽、数量、控制距离与返航状态 |
| 铁骑 | `LaunchSquadron`、`RecallSquadron`、`UseAbility` | 编队/能力身份、次数、冷却、目标与成员状态 |
| 舰船模式 | `SwitchMode` | 可用模式、切换条件/冷却、原子撤销/添加效果；不当作普通装卸装备 |

模块激活的参数由能力定义：锁定型攻击携带 targetId，自身中心脉冲可无目标，定向炸弹可携带合法发射方向。不能要求所有能力都有锁定目标，也不允许脚本指定实际 AOE 命中集合或闪电次级目标来绕过机制选择规则。

电子战限制以带来源的上下文谓词进入意图校验，并在能力实际开始/继续时按规则复核。需要区分锁定开始、维持、破锁和禁止再锁定，支持定向 ECM 对来源目标的例外；瞬时破锁不自动生成持续干扰。范围、概率、效果抗性和维护/结束策略见 [电子战架构](electronic-warfare.md)。

意图携带 controllerId（由宿主绑定，不信任脚本自报）、decisionTick、observedWorldRevision、实体/模块 ID、commandId。相同 commandId 重试幂等。

收据区分 `accepted`（已进入队列）、`started`、`completed`、`rejected`、`cancelled`。接受不等于已经命中或未来必定执行；目标离开/毁灭时通过事件说明。错误码包括 `NOT_OWNED`、`STALE_OBSERVATION`、`TARGET_NOT_VISIBLE`、`TARGET_NOT_LOCKED`、`OUT_OF_RANGE`、`INSUFFICIENT_CAPACITOR`、`NO_AMMO`、`ABILITY_COOLDOWN`、`CONTROL_CONFLICT`。

重复 `KeepRange` 更新导航目标，不无限追加任务；周期中重复相同攻击意图不重复扣电。每个实体默认一个控制者；手动接管在边界事件生效并使该实体本轮冲突脚本意图失败，接管/释放都写日志。

## 4. JS 策略 API v0 草案

每个控制者拥有独立的 JSON Memory，入口是纯交互函数：

```ts
type DecisionInput = {
  observation: Readonly<ControllerObservation>;
  memory: JsonValue;
  random: { next(): number }; // 受引擎管理的策略随机流
};

export function tick(input: DecisionInput): {
  memory: JsonValue;
  intents: BattleIntent[];
};
```

`observation` 包含本次时间/版本、自己控制的实体、传感器允许的 contacts、上一边界以来的可见事件和命令收据。自己舰船的模块有能力标签、状态、资源、冷却等；对手未知装配、电容和脚本 Memory 不能因为计算内核知道就提供给脚本。

可见性有两种明确 profile：全知教学与玩家观测。全知回放查看器是分析权限，不改变脚本所见；玩家观测中未知字段省略或使用 `unknown`，不能返回 0 冒充已知。观察记录测量时刻，丢失接触不保留实时隐藏数据。

示例策略见 [kite-policy.mjs](kite-policy.mjs)：多艘己方船选择最近可见敌船、保持距离、请求锁定、锁定后启动武器。它只演示拟议接口，不承诺能直接在当前 FitLab 运行。

策略持久状态只能放在 Memory。每次决策使用新的执行上下文，模块顶层变量不会偷偷跨 tick 保留；编译结果可缓存，执行全局状态不缓存。Memory 与整批输出意图在函数成功、序列化校验通过后一起提交；抛异常或超预算丢弃本轮输出和 Memory 变更。

初期 API 保持同步；不支持脚本 Promise、网络回调、文件、宿主进程、真实时钟或不受控随机源。标准数学与序列化能力由白名单明确。脚本可以写受限日志，日志受大小和数量预算约束。

## 5. 脚本运行隔离与确定性

脚本是用户运行的程序，运行隔离是产品能力：一段无限循环不能卡住 UI 或损坏另一场实验。

- 初选独立 ScriptWorker 承载 Jint；实施阶段实测预算/隔离能力，再冻结运行时和 API 版本。单独的普通 JS VM 不被视为完整进程边界。
- 确定性执行预算用于定义脚本行为；宿主墙钟超时和进程内存上限属于基础设施保护，不可把机器变慢造成的超时直接判成策略战败。
- 预算耗尽：策略本轮无新意图、Memory 不提交，既有世界动作按自身状态继续；重复失败可按实验策略终止控制者或中止实验，策略固定在 manifest。
- 基础设施错误将 run 标成 `infrastructure_error`，不能混入胜率分母假装是正常败局。
- 随机流区分世界战斗、各控制者、各机制，并以稳定实体/能力/事件序号建立计数域；增加无关日志或运行线程不应消耗世界随机数。
- 墙钟、系统区域、字典遍历次序、worker 完成顺序和字符串本地化排序都不能影响世界结算。

数值提案：模拟时间用 int64；属性/几何使用明确版本的数值方案，先验证 double 运算与量化边界、非有限数和跨平台数学差异。首批确定性承诺限定同引擎构建/架构/规则版本，检查点哈希必须一致；跨平台逐位复现未经验证不能承诺。比较用的容差与 replay 的精确哈希不是一回事。

## 6. 回放、复算、恢复、分叉是四件事

| 操作 | 输入与行为 | 保证 |
| --- | --- | --- |
| 回放 | 读取记录的快照/事件，渲染状态 | 不需要再次运行 JS，也不从当前规则猜旧结果 |
| 复算 | 使用固定版本、输入、种子和控制记录重新执行 | 在约定确定性范围内核对检查点哈希 |
| 恢复 | 加载完整检查点继续原 run | 未结算事件、资源和 Memory 均恢复 |
| 分叉 | 从边界检查点创建新 run，可更换脚本或命令 | 原 run 不变；记录父 run/检查点与变更 |

检查点必须包含：世界实体、活动效果/来源、位置速度、锁定进度、模块/编队能力状态、弹夹与货舱、飞行物、事件队列、随机流计数、所有控制者 Memory、控制权和观察序号。只保存 HP 与位置不算可恢复快照。

特殊机制状态也必须入检查点：每武器/目标预热、炸弹引爆计时/载荷、导弹制导和寿命、未完成次级攻击的选择/传播状态、舰船模式与切换冷却、独立无人机/铁骑成员状态。已发生事件的采样参数随事件保存，恢复后不能用新状态追溯替换。

导弹被适用 AOE 摧毁是必做交互：检查点还需保存导弹剩余耐久、终态及事件代次；被摧毁导弹的待命中事件失效，不得在恢复后复活或造成幽灵伤害。逐弹拦截与分析验收见机制设计 M03-A。

电子战检查点保存每个效果的来源/目标、持续与刷新状态、约束实例、空间场成员、锁定进度、下一次判定和已抽取结果。恢复时不重新抽取已发生的 ECM 判定，不把多个来源压成一个无法正确解除的布尔状态。

分叉默认保留逻辑模拟时间，不把计时器归零后假称同一起点；图表可显示相对分叉时间。脚本版本更换和初始 Memory 是否继承作为分叉参数记录。新数据或新引擎不自动替换旧 run 的规则包。

事件含 runId、sequence、simTime、phase、source/target、causeEventId、ruleId、前后值、随机抽样引用与覆盖状态。射击可追到指令、资源预留、发射、命中、抗性和跨层损伤。日志接收时固定 run 上下文，晚到日志不写进下一轮。

实验状态：`created → preparing → ready → running → pausing/paused → stopping → finalizing → completed`，另有 `failed/cancelled`。`completed` 只在最终检查点、指标和证据落盘后发布；停止计算并不立即等于结果已齐全。

## 7. 比较与批量实验

基础实验包固定：蓝图/角色/实例版本、初始资源、位置速度、环境与可见性、规则/运动/时间模型、脚本/初始 Memory、种子及结束条件。

比较先核对 `comparability` 与 `evidenceCompleteness`，再比较指标。候选与基线只能按实验设计声明的变量不同（例如只换某控制者脚本）；其他差异返回 `incomparable`。缺失数据返回 `insufficient_evidence`，不能说“没有变化”。

输出支持胜负/时间上限、存活、造成/承受伤害、命中与换弹损失、有效/溢出维修、电容失败、弹药消耗、关键事件和脚本错误。击毁时间在时间上限未击毁时是删失/未达到，不把超时长度当作真实击毁时间。

机制分析按根激活、子事件、目标与阵营归因，并提供覆盖热图、在途伤害、预热重置、次级传播图和模式时间线。对照支持固定控制与重新运行策略两种不同语义；改动机制本身的反事实实验使用显式规则变体，详见机制文档。

随机战斗使用成对种子集和样本量，报告胜率区间及分布；不能仅凭单局更快就说策略更好。采用公共随机流域降低无关噪声，但不承诺策略改变后所有随机事件仍一一对应。

先验收顺序执行与并行执行结果一致，再扩展批量吞吐。MCP 批处理返回 jobId，支持进度、取消和分页事件，不一次倾倒全部日志。

## 8. 最小纵切的验收脚本

1. 两艘固定蓝图的船，独立绝对速度与位置；手动与 JS 分别完成锁定、移动和逐轮开火。
2. 同场景/脚本/种子执行两次，对齐全部边界状态哈希。
3. 单步、连续运行与检查点恢复结果一致；改变渲染帧率或 worker 数量不改变胜负。
4. 同刻双方足以致命的合法攻击允许同时毁灭；调换阵营标签不产生固定先手优势。
5. 锁定未完成、失去目标、缺电、换弹、重复命令都有准确收据和资源守恒检查。
6. 脚本无限循环/异常/非法 Memory 不污染世界和其他控制者，不被误统计为正常战败。
7. 分叉只改脚本，保留其他条件；原回放不变，比较能说明实际改动。
8. 玩家观测中不泄露对手电容/配装/Memory；全知回放不使脚本突然获得隐藏状态。
9. 普通配装静态纸面值，在对应固定、无资源中断的实验前提下，与逐轮模拟的长期均值一致。
10. 一艘航母/铁骑能力与两件深渊实例能进入同一世界模型，未实现行为明确拒绝，不能退化成普通无人机或普通装备。
