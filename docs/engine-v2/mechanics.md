# 特殊机制：可组合模拟与影响分析

状态：V2 设计增补 v0.2，2026-09-14；尚未实现。来源为用户本轮补充，以及本地 SDE 3248221 的代表类型/属性。数值存在于 SDE 不等于全部行为已验证；触发、选择目标和状态重置等运行语义要有独立证据。

## 1. 设计要求

引擎必须能表达范围攻击、独立飞行物、延迟生效、持续累积、次级目标传播、舰船模式切换及自主作战单位。每个机制同时交付：**运行规则、可保存状态、解释事件、分析查询和验证案例**。没有这五项，不能把“面板显示了 DPS”算作支持该机制。

静态属性图负责“此刻属性是多少”；行为系统负责“什么时刻、什么条件、对哪些对象、执行什么效果，以及随后进入什么状态”。属性修正无法独自表达一枚飞行中的炸弹，行为事件也不能另建一套伤害/抗性公式。

复杂电子战作为 M09 机制族，详细扩展见 [电子战架构](electronic-warfare.md)：包含属性效果、来源相关行动约束、瞬时破锁、空间控制场、概率与双实体资源闭环，共享本文件的注册、事件、分析与验证契约。

```mermaid
flowchart LR
    A[能力定义与触发条件] --> B[资源预留 / 状态机]
    B --> C[即时效果 / 未来事件 / 派生实体]
    C --> D[同一时刻的空间查询与目标选择]
    D --> E[逐目标应用与结算]
    E --> F[结果事件 / 状态变化]
    F --> B
    F --> G[时间线 / 因果解释 / 对照实验]
```

## 2. 机制扩展契约

### 2.1 共用构件

| 构件 | 负责的事情 | 示例 |
| --- | --- | --- |
| ActivationPolicy | 是否需要锁定、可用模式、环境限制、目标限制 | 智能炸弹无需选择单一锁定目标；炮塔攻击需满足自己的锁定规则 |
| ResourcePlan | 本轮电容、弹药单位、能力次数、冷却预留 | 铁骑特殊攻击消耗有限次数 |
| Delivery | 效果如何到达世界 | 立即脉冲、指定时刻完成、飞行实体、持续区域 |
| SpatialQuery | 在明确时间和几何口径下查找对象 | 球形范围、主目标附近、运动轨迹区间 |
| TargetSelection | 类型、阵营、本人/主目标排除、数量、排序/随机规则 | AOE 不能默认只命中敌人 |
| Payload | 作用内容 | 伤害向量、电容损失、维修、电子战状态、属性修正 |
| StatePolicy | 累积、重置、衰减、切换与结束条件 | 预热进度与锁定目标绑定 |
| SamplingPolicy | 属性与对象状态在何时读取 | 发射时的源参数，命中时的目标抗性 |
| ExplanationPolicy | 保留哪些因果、空间和状态信息 | 为什么命中 A，为什么未选择 B |

构件共享不代表所有武器都使用相同命中算法：炮塔跟踪、导弹签名/速度减伤、炸弹效果和范围脉冲分别选择适用的 application model。友军/中立/无人机/飞行物是否可受影响，按该机制规则选择。

### 2.2 新机制的注册内容

每个 `MechanismDefinition` 包含稳定 ID、版本、类型/效果绑定、所需能力依赖、状态 schema、触发事件、输出事件、采样规则、目标规则、分析器、证据/覆盖状态和测试集。

常见组合用声明式能力配方；复杂拓扑和状态机允许注册受控 C# 处理器。处理器接收只读世界视图、版本化规则和自己的状态，返回待校验的状态迁移、资源操作、事件或派生实体；不直接改其他实体 HP，也不访问墙钟、文件或自建随机源。

基础设施统一负责身份、调度、空间查询、随机流、提交、日志和检查点。添加机制通常增加注册配方/处理器、状态序列化、分析器和测试，无需修改总 DPS 聚合、主战斗循环或前端伤害计算。

不建设任意可执行脚本组成的无限通用规则语言。玩家策略 JS 只能提交战术意图；机制处理器属于经过验证的规则包，两者权限和版本独立。

### 2.3 事件身份与状态采样

每次激活有 `activationId`；其所有飞行物、爆炸、次级命中、状态增量携带 `rootActivationId` 和 `causeEventId`。次级伤害不再次触发一次完整武器激活，不重复扣弹药或电容。

采样点必须逐参数定义，不能统一“全部发射时冻结”或“全部命中时重算”。例如源伤害参数、目标移动状态、目标抗性、预热阶段、模式加成分别规定读取时点。来源死亡、模式切换和换目标不能无依据地追溯修改已经发射的攻击。

实体删除使用明确的存活状态和来源引用；已离场来源仍能用于日志归因。飞行物是否继续存在由自身规则决定，不能因为所属舰船对象从容器移除就自动消失。

## 3. 用户列举机制的正式模型

### M01 立体炸弹 / Smartbomb：以舰船为中心的范围脉冲

配方：`Activate → PayResources → PulseAtSourcePosition → QuerySphere → FilterEligibleEntities → ApplyPayloadPerTarget`。

- 脉冲中心取实际生效时刻的舰船位置，半径使用该装备范围属性；不能使用普通炮塔的 maxRange/falloff 替代。
- 同一轮只支付一次资源，受影响目标可以有多个；每个目标分别应用适用规则和抗性。
- 是否包含己方、中立、无人机、铁骑成员、导弹/炸弹等，由明确的可命中对象表决定，不以“脚本是否看见目标”决定真实效果。
- **导弹被适用 AOE 摧毁是明确必做能力**（用户 2026-09-14 补充），立体炸弹拦截在途导弹必须实现。对飞行物的摧毁与对舰船的伤害是不同目标类型的结算；其他 AOE/飞行物类别的适用表、数值和同刻引爆/拦截优先级逐项核准，不默认所有范围效果都能伤害所有飞行物。
- 几何采用舰船中心距离、表面距离还是其他口径必须标记；边缘采用统一精度策略，不任意加 epsilon 扩大攻击范围。

分析：单轮覆盖数、逐目标伤害、敌方/友方/中立损失、拦截结果、每 GJ 收益、脉冲时刻的空间截面。无场景时只显示单目标名义单轮量/周期/范围，不给虚构的总 AOE DPS。

验证：边界内外；目标在启动后进出范围；多目标只扣一轮资源；隐藏但可命中实体；飞行物交互；两个同刻脉冲；单步/恢复等价。

### M02 炸弹发射器：独立投射物与区域载荷

配方：`Launch → SpawnBomb(position, direction, motion, lifetime) → Flight → DetonationTrigger → AreaPayload → Despawn`。

- 发射器的重激活延迟、弹药和激活限制归发射器；飞行轨迹、引爆条件、生命期、可被攻击属性和载荷归炸弹。
- 普通炸弹按实际飞行/引爆机制实现，不默认等同静止地雷或追踪导弹。引爆位置来自炸弹实体，发射船移动不能拖着爆炸区域走。
- 载荷可以是伤害、电容战或电子战；“炸弹”并非只能封装四种伤害。
- 爆炸时重新查询范围内实体，逐目标应用适用的签名/抗性或其他规则；炸弹间能否互相影响和是否引发后续事件按类型验证。
- 发射者死亡、炸弹提前被摧毁、到期与目标进出范围分别有结果事件。

分析：发射至引爆延迟、预测/实际引爆位置、覆盖热图、命中目标构成、弹幕重叠、友伤、未引爆原因、每枚载荷收益。预测轨迹明确假设，敌人未来移动未知时不是保证命中。

验证：直线飞行、转向后发射、新旧炸弹互不跟随船体；引爆边界；来源死亡；提前摧毁；伤害/电容/电子战载荷；多炸弹同刻结算。

### M03 导弹：有生命周期的追踪飞行物

配方：`Fire → MissileEntity → Guidance/Motion → ReachTarget or Expire/Destroyed → Application → Damage`。

- 发射即消耗弹药并安排下一轮，命中发生在之后的事件时刻；“在途伤害”与“已造成伤害”分开。
- 保存目标引用、运动状态、寿命、发射来源和采样参数；根据版本化模型处理目标移动、失效、离场、速度变化及可用拦截机制。
- 不把飞行时间永远简化为发射时距离/最大速度。可以提供明确标记的近似模型，但不能与已验证飞行模型混在同一实验里不作说明。
- 应用使用目标自身速度与签名等参数；不把舰船间相对速度当成导弹减伤速度。

分析：首发命中时间、发射/命中吞吐、在途弹数与在途名义伤害、过量集火、目标先死亡导致的失效、射程边界损失、距离变化对击毁时间的影响。

验证：静止/接近/远离目标；多个齐射同时在途；寿命到期；被拦截；来源死亡；目标失效；暂停和恢复不丢在途弹。

#### M03-A：AOE 摧毁在途导弹（必做）

导弹是可受适用范围伤害的实体，具有独立耐久、适用的伤害抗性/修正和 `inFlight / impacted / expired / destroyed` 生命周期。耐久与修正从该类型及有效规则求值；不能给所有导弹写死相同耐久，也不能把进入范围直接等同必定被摧毁。

结算链：`AreaPulse → QueryEligibleMissiles → ProjectileDamage → DurabilityChange → ProjectileDestroyed`。只在 AOE 实际生效时刻检查导弹位置；导弹在两次立体炸弹脉冲之间穿越范围，不因曾经经过而被追溯命中。持续区域效果则按其独立的持续触发规则判定。

- 每枚导弹分别记录剩余耐久，可以承受多次非致命 AOE；同刻多次范围命中按统一阶段批量结算。
- 摧毁时使该导弹尚未执行的制导/命中事件失效；队列条目即使尚未物理删除，执行时也必须校验生命周期/事件代次，不能产生幽灵命中。
- 终态只能提交一次；同刻命中与摧毁按已固定的规则优先级处理，不双重结算。已经完成的命中不追溯撤销，已发射弹药和电容也不因被拦截返还。
- 同一齐射中只摧毁部分导弹时，其余导弹继续正常飞行；可聚合展示齐射，但不能把整个齐射当作共享一份耐久的对象。
- 检查点保存部分受损导弹的耐久、生命周期及未执行事件代次。恢复后不得复活已摧毁导弹或重置非致命损伤。

分析至少提供：发射/到达/被 AOE 摧毁/到期/目标失效数量、拦截位置与时刻、伤害来源、被拦截的在途名义载荷、实际穿透输出及按时间窗的拦截比例。显示比例时明确分母，例如已离开发射阶段的导弹数；观察窗口结束时仍在途的导弹单列，不能算作拦截成功。

“拦截使本次到达输出减少多少”可从事件统计；“最终避免了多少 HP 损伤/是否避免被击毁”需要对照实验，因为被拦截弹药可能原本也会过量、到期或打到不同抗性状态。后者不能直接等于被拦截弹药的名义伤害。

必须验收：单次非致命/致命 AOE、连续脉冲累积、脉冲间穿越、范围边界、多枚只毁部分、同刻多个 AOE、摧毁/命中同刻、源舰死亡、部分受损检查点恢复和已销毁事件重放；GUI 回放与 MCP 查询均能追到具体导弹和拦截来源。

### M04 三神裔熵能分解炮：按武器/目标持续积累的状态

配方：`StartAttack → CycleWithCurrentSpool → RuleDefinedAdvance → Repeat`，由明确中断事件控制重置/保持/衰减。

`SpoolState` 至少含武器实例、当前目标、已积累周期或增益、上次有效推进时刻、状态和重置原因。它不是一个全舰共享的“开战经过秒数”。

- 每周期增益、上限、初始值从有效规则读取；不同武器、不同目标互不串进度。
- 本轮使用推进前还是推进后增益、未命中是否推进、短暂出射程/断锁/缺电/停机/换目标/换弹是否重置，都属于显式机制规则和验证项，不能凭视觉或名称猜测。
- 船体/技能/装备改变预热参数时，当前进度和既有周期如何处理也需明确。
- 可复用状态积累构件支持预热维修等能力，但触发与重置表按能力各自定义。

分析：每轮倍率与实际伤害、到达上限时间、实际平均预热、重置次数和损失、保持目标/频繁转火的击毁时间与输出差异。静态面板分别给初始/上限/指定持续条件，不把最高 DPS 标成常态 DPS。

验证：首轮/第二轮/上限边界；独立武器与目标；各种中断；状态恢复；自适应脚本转火实验。

### M05 EDENCOM 涡流投射器：受限的次级目标传播

配方：`PrimaryAttack → SelectSecondaryTargets → PerTargetApplication → GroupedOutcome`。

- 拓扑显式定义为“围绕主目标选次级目标”或其他经过核准的规则。不能因为画面有闪电就实现无限逐跳传播，也不能把次级目标继续当成新的武器发射源。
- 选择中心、半径、总/次级数量上限、排除集合、是否允许重复命中、目标类型、阵营限制、排序或随机方式分别记录。SDE 有范围/数量属性不代表已说明选择算法。
- 主目标与次级目标分别运行适用的命中/减伤规则；不能把主目标实际伤害直接复制到不同签名/速度/抗性的次级目标。
- 记录选择时刻；目标在选择后离开/死亡如何处理由投递策略规定。需要随机选目标时，使用本次激活专属随机域。

分析：主目标/次级贡献、实际覆盖数、传播连接图、候选/入选/排除原因、聚集与分散队形差异、友伤、目标选择不确定性。攻击事件用根激活归组，避免把一次攻击统计成多次耗弹。

验证：超过上限的目标群；等距候选；没有次级目标；不同抗性/速度目标；友方/中立候选；主目标消失；相同种子重现选择；改变实体容器顺序不改变结果。

### M06 战略驱逐舰：运行时模式状态机

模型：`ShipModeState {currentMode, requestedMode, transitionState, readyAt, effectHandles}`，对应 `SwitchMode` 意图。

- 模式定义来自数据和规则，不作为玩家能随意装卸的普通装备塞进槽位。T3 战略巡洋舰的子系统与战略驱逐舰模式是不同概念。
- 切换校验可用模式、冷却与状态，原模式效果撤销、新模式效果添加在一个原子边界完成，避免两套模式临时叠加。
- 切换使相关属性依赖失效；实际速度和位置不瞬间改成新最大速度，运动依规则趋近。已经在途的攻击、已安排周期、锁定集合、HP/电容容量变化如何处理由采样/状态转换规则约束。
- 静态装配可比较各模式；战斗读取当前实际模式。模式变更进入检查点、观察与回放。

分析：各模式属性差量、停留时间、切换时机、冷却阻塞、切换前后生存/追击/输出变化。能从一次死亡前的检查点分叉比较“提前切防御”和“保持攻击”的结果。

验证：非法模式、冷却中重复切换、原子移除/添加、往返切换不累积加成、在飞行/射击中切换、重放恢复。

### M07 普通无人机：拥有运动和生存状态的独立单位

模型包括在舱、发射、跟随/追击、环绕攻击、返航、控制受限、失联/死亡等适用状态；出动、攻击和返航的完成是世界事件。

- 以可伤害、可移动实体参与空间查询。显示同类数量聚合时，不能抹掉个体位置、HP、追击和攻击时序差异。
- 控制距离、带宽、目标指令、主动行为规则与所有者损失分别定义；追击未到攻击条件时不能贡献满 DPS。
- 严格实验中无人机能力参数来自同一效果图；被网/被炸/受远程作用时进入正常效果系统。

分析：在舱/追击/攻击/返航占比、首次输出延迟、损失与召回保全、对小目标的应用、为何纸面无人机 DPS 没有兑现。

### M08 铁骑舰载机：编队与成员、多个能力

沿用主设计的 `FighterSquadron + AbilityInstance`，进一步明确编队展示和成员结算的边界。

- 编队级指令与成员存活数量、伤害分配、空间代理/成员位置之间使用有版本的表达；如果某机制会区分成员，不能用没有说明的“编队单一 HP 球”替代。
- 普攻、特殊攻击、推进等能力各有状态、次数、周期和冷却。能力间互斥/并行、重装、召回、控制约束和成员损失导致的输出变化都由规则决定。
- 以同一资源预留与事件系统发射飞行物、施加范围效果或推进，不另开“航母模拟器”计算旁路。

分析：每项能力输出、有限次数的爆发分配、冷却空档、追击收益、成员损失曲线、召回时机和剩余战斗能力。

## 4. 空间查询与事件相互作用

空间索引提供版本化的 `QuerySphere`、邻域查询、轨迹区间/扫掠查询等能力，但查询结果必须经过机制自己的目标筛选和精确几何复核。索引加速不能改变目标集合或排序。

所有查询注明 worldRevision、simTime、查询中心/形状、距离口径、筛选器和选择策略。实体正好进出范围、移动物跨过区域或同刻被摧毁时必须有统一边界语义；高速度飞行物不能因步长较大跳过需要判定的交互。

物理碰撞、被攻击命中与可见性是三种关系，不能因为碰到空间包围球就认为所有飞行物都被其他舰船挡住。是否存在拦截/遮挡等行为由对应机制决定。

原子效果提交之后再产生后续因果事件，给传播设置规则内的上限及重复访问策略。基础设施预算耗尽不能悄悄截断 AOE 目标或跳过后半段闪电后仍报告正常完成，应返回不完整/失败状态。

## 5. 如何方便分析机制影响

### 5.1 三层分析

1. **配装预览**：机制参数和条件范围，如脉冲半径、引爆延迟、初始/上限伤害、模式差量、能力次数。没有目标分布时不虚构多目标收益。
2. **单次战斗解释**：机制状态时间线、空间截面、逐目标贡献、命令/状态/伤害因果图；支持点击一发炮、一枚炸弹或一次模式切换定位。
3. **对照实验**：从相同检查点改变阵形、开火时机、目标选择、模式策略或某项实验参数，运行配对种子，比较结果与分布。

分析 API 草案：

- `describe_mechanism(typeOrInstanceId, ruleset)`：能力、参数、覆盖状态、支持的分析。
- `inspect_activation(runId, activationId)`：资源、采样参数、状态前后、所有子效果。
- `explain_target_selection(runId, eventId)`：为何入选/排除、几何和选择规则；大集合分页。
- `query_mechanism_timeline(runId, entityId, mechanismId, timeWindow)`：预热、模式、追击、冷却等。
- `query_contributions(runId, filter, groupBy, timeWindow)`：按机制/能力/实体/目标/阵营聚合实际结果。
- `compare_mechanism_variants(experimentSpec)`：明确变量、控制方式、种子与指标的实验作业。

脚本观测、玩家回放和全知分析分别鉴权；能查询全世界 AOE 候选不等于玩家脚本能读取隐藏目标。

### 5.2 不能混淆的结论

- 实际事件归因回答“这次命中了谁、造成多少”；反事实重跑回答“改变机制/策略后结果怎样”。前者不能单凭伤害账单推断后者。
- 禁用预热、取消飞行延迟或禁用次级目标等属于实验干预，必须标记为非标准规则变体，不能冒充实际游戏装配结果。
- 固定命令记录重跑用于隔离机制变化，但命令可能在新世界中失效，须报告有效性；重新运行脚本则包含策略反馈。两者分别标为固定控制与自适应控制，不混合统计。
- 机制间有交互。例如切推进改变签名/速度，影响导弹应用，也改变进入 AOE 的时机；不能把各自独立收益相加当成总收益。必要时跑 A、B、A+B 与基线四组，单独报告交互项。
- AOE 的“总有效伤害”要分敌方/友方/中立；范围击中更多目标不自动代表战术收益更大。

## 6. 跨机制验证矩阵

| 组合案例 | 要证明的边界 | 必备分析结果 |
| --- | --- | --- |
| 立体炸弹 × 在途导弹（必做） | 耐久累积、部分拦截、脉冲时刻与终态互斥；被毁弹不再命中 | 逐弹拦截因果链、在途/穿透/被毁统计 |
| 范围武器 × 无人机 | 适用对象与同刻命中次序正确 | 受损/死亡因果链、单位损失 |
| 飞行炸弹 × 移动编队 | 引爆位置与引爆时目标集合正确 | 空间覆盖与逐目标效果 |
| 预热炮 × 转火/断锁/缺电 | 每武器目标状态按规则重置/保持 | 重置原因与输出损失时间线 |
| EDENCOM × 聚集/分散队形 | 范围、数量、目标规则与次级应用正确 | 传播图和目标选择解释 |
| 模式切换 × 在途导弹 | 源参数和命中时目标参数按各自规则采样 | 命中前后模式/速度/签名/抗性 |
| 模式切换 × 当前周期 | 不产生双重加成或追溯改写已发生事件 | 效果撤销/添加及计时依据 |
| 无人机 × 范围武器/召回 | 个体运动、损失与返航不是固定 DPS 折扣 | 存活、状态耗时与资源变化 |
| 铁骑 × 特殊攻击/成员损失 | 能力次数和成员数量不被重复消耗或恢复 | 编队能力与成员损失曲线 |
| 任意组合 × 保存/恢复/分叉 | 飞行物、预热、模式与能力状态完整恢复 | 检查点哈希、重算与连续运行一致 |

测试按规则状态、边界、数量、随机选择、来源死亡和交互分类；扩大类型覆盖时可复用模板，但预期来自已核准行为。静态参考软件通常只能支持部分属性/公式验证，完整战斗机制需要客户端实验记录或其他独立证据。

## 7. 实施顺序与覆盖清单

将原阶段 B 扩成“架构能力验证”：普通单炮脚本战斗纵切之外，用小型、明确标记为非游戏数值的测试配方验证范围脉冲、独立投射物、累积状态、次级目标选择和模式切换的表达能力。合成配方只证明框架，不能宣称相应 EVE 装备已支持。

随后阶段 D 按 M01–M08 逐项绑定真实类型、核准行为、通过独立和组合验证、交付分析器。每项分别记录：数据已识别、行为已实现、轨迹可解释、检查点完整、独立验证、组合验证和产品入口，不用一个 `supported=true` 混淆这些层级。
