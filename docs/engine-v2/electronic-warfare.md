# M09 电子战：效果生命周期、控制约束与战斗闭环

状态：V2 设计增补 v0.3，2026-09-14；架构与验收契约，尚未实现。用户要求：各种复杂电子战必须能在架构中模拟，并分析其实际影响。

## 1. 核心要求

电子战进入同一个真实世界，影响锁定、模块启动/维持、导航、资源、应用伤害和后续策略观察。不能仅在面板展示“减速 60%”而让目标继续按未受影响的速度战斗，也不能用一个总电子战抗性百分比处理所有机制。

电子战能力复用 [机制构件](mechanics.md)，分为四种可组合输出：

1. **属性效果**：改变速度上限、签名、扫描分辨率、射程、跟踪等。
2. **行动约束**：限制能锁定谁、能启动哪些能力、是否能跃迁等。
3. **一次性状态操作**：打断现有锁定、排定状态迁移或施加一次资源损失。
4. **空间场/持续关系**：根据在场条件、来源/目标关系及周期决定效果存在与否。

数值属性图、控制约束系统、空间系统、资源账本和事件调度共享来源身份与时间。一次效果导致的后续变化必须形成因果链。

## 2. 机制族与必须能表达的规则

| 机制族 | 正式模型 | 必须区分的行为 |
| --- | --- | --- |
| 定向 ECM | 周期成功判定 + 来源相关的锁定约束 | 感应器类型/强度、范围判定、现有锁定、持续时间、对干扰来源的锁定例外、多来源组合 |
| ECM burst / 范围破锁 | AOE 选择 + 逐目标判定 + LockBreak | 瞬时破锁与持续禁止锁定分别建模；阵营/对象/范围条件 |
| 感应抑阻 | 扫描分辨率/最大锁定距离效果 | 脚本选择、叠加、锁定进行中与既有锁定的处理 |
| 炮塔扰断 | 炮塔属性作用域 | 最佳/失准/跟踪分量与脚本；只影响适用能力 |
| 导弹制导干扰 | 导弹相关属性作用域 | 飞行/应用参数、脚本与采样时点；不能套用炮塔跟踪公式 |
| 目标标记 | 目标签名效果 | 船体/技能、叠加、范围；签名变化进入适用的锁定与伤害公式 |
| 网子 / 停滞缠绕 | 运动参数效果 | 速度上限变化与实际速度演化分开，按适用叠加组处理 |
| 停滞捕捉类能力 | 距离相关效果强度 | 效果强度衰减、成功概率衰减与硬射程三种函数独立选择 |
| 扰断 / 扰频 | 跃迁强度关系 + 能力禁止规则 | 有限强度相加、稳定强度、不同推进/跳跃能力、例外对象；不当作百分比减益 |
| 重型拦截与拦截场 | 特殊强度 / 空间约束 | 聚焦与场模式、脚本、区域进入/离开、免疫/无效化、环境限制 |
| 毁电 / 吸电 | 资源事件与双实体条件 | 源舰付出、目标实际剩余电容、效果抗性、适用签名缩放、吸电条件与船体例外 |
| 电子战无人机 / 铁骑能力 | 移动作战单位发出的同类能力 | 追击、控制、能力冷却、个体来源、叠加/概率规则独立核准 |
| 反制及相关支援 | 类型化抗性/免疫 + 属性/约束修正 | 感应增强、远程支援、模式/特殊状态、稳定/无效化；正面与负面效果按规则组合 |

这张表定义架构覆盖面，具体参数和特殊例外需按类型、版本验证。不能将“已能表达”标成“所有 EVE 规则已验证”。毁电/吸电等相关控制机制也纳入同一闭环，分类名称不决定它们共用一套公式。

## 3. EffectInstance：每个效果保留完整身份

运行时实例至少包含：

```text
effectId / definitionId / definitionVersion
sourceEntityId / sourceAbilityId / activationId / rootCauseEventId
targetEntityId 或明确的目标集合/空间场绑定
scope / targetPredicate / effectFamily / polarity
startTime / endTime / nextEvaluationTime
sampledParameters / liveDependencies
stackingGroup / combinationPolicy / resistancePolicy / immunityPolicy
maintenancePolicy / removalPolicy / refreshPolicy
state / generation / randomDomain / applicationOutcome
```

- 相同装备的多个来源仍是独立实例；一个来源停止时只移除相应效果，重新计算余下的叠加。
- 刷新、叠加新实例、延长持续时间、覆盖旧实例是不同策略，不能统一“重新添加一次”。
- 效果结束撤销贡献并按依赖图重算，不能用除回上次数值的方式恢复属性。
- 来源死亡、离场、缺电、被干扰、主动停机、失去目标或距离变化是否立即移除/等周期结束/不影响已经发出的效果，必须由该能力维护策略定义。
- 目标毁灭、进入不适用状态或免疫状态时如何处理已有实例也需声明。事件代次避免过期队列条目再次施加或再次撤销效果。

## 4. Range、概率、强度、抗性分别定义

每个效果声明自身处理管线与顺序，不能全局强制使用同一条概率公式：

`eligibility → immunity → range policy → applicable resistance → chance/strength → stacking/combination → state change`

此顺序是可描述的管线示意，实际步骤先后取决于版本化机制。每一步保留输入、输出和跳过原因。

### 范围

`RangePolicy` 包括硬门槛、概率型失准、强度型衰减和空间场成员关系。最佳/失准字段由具体机制映射，涵盖 `falloffEffectiveness` 等不同属性；缺失射程不得默认为 1 m。

移动中的目标需要在规定采样时刻读取距离。离开范围是“下一轮不能成功”“当前效果立即解除”还是“剩余周期继续”由维护策略决定；不能每帧对所有效果自动解除。

### 概率

每次合法机制判定只抽样一次，并绑定激活/周期/目标和随机域。读取解释、渲染、暂停、重算属性不重新摇骰。多个 ECM 来源分别记录各自结果；叠加后的控制覆盖时间从实际状态算出。

单个周期、固定条件下可以给出期望成功率；不能拿静态联合概率代替不同周期和持续时间交错的控制时间线。

### 强度与叠加

属性乘数、百分比、有限点数、强约束、持续时间组合分别有 reducer。普通叠加惩罚沿用统一验证实现，但只有声明适用的效果进入该叠加组；不能给跃迁扰断点数也套百分比惩罚。

特殊“无限/不可由有限稳定抵消”的约束使用语义标签及兼容规则表示，不用 `999999` 或 Infinity 塞进数值属性。多来源的去重、排序、正/负方向、刷新和例外有独立测试。

### 抗性与免疫

目标使用按机制族和上下文匹配的防护定义。防护可以降低强度、改变判定、减少持续时间或完全拒绝；不能把它们都当作乘 `(1-resistance)`。

模式、特殊模块状态、技能和船体例外能动态改变这些定义。免疫某种目标电子战不自动意味着免疫范围控制、毁电或所有远程效果；相关条目分别登记。

## 5. 控制约束不是一个 jammed 布尔值

世界提供带上下文的能力判定：

```text
CanStartLock(actor, target, time)
CanMaintainLock(actor, target, time)
CanStartAbility(actor, ability, target, time)
CanContinueCycle(actor, ability, time)
CanNavigate(actor, navigationKind, time)
CanWarp(actor, destinationContext, time)
```

返回允许/拒绝、原因码和产生约束的 effectIds。定向 ECM 的“仍可针对干扰来源锁定”等规则通过来源相关谓词表达；多个来源共同作用时使用已核准的组合策略，不能随意做允许集合的并集/交集。

锁定状态有请求中、进行中、完成、被打断等阶段。破锁事件与禁止重新锁定的持续约束分开；扫描分辨率改变时是否重排正在进行的锁定、最大距离改变时如何处理已有锁定，明确注册并验证。

脚本提交时满足条件不代表能力开始时仍满足：排队命令在执行点复核，周期性能力按继续策略复核。锁定失效后已飞行导弹、无需锁定的范围能力和正在运行的导航分别遵循自己的机制，不一起强制停止。

## 6. 进入实际战斗的闭环

示例：目标标记使签名变化 → 属性图更新 → 后续适用的锁定/导弹命中读取该签名 → 命中结算 → 事件归因到标记效果。发射时冻结的参数仍保留原快照，不能追溯修改。

示例：扰频产生推进能力约束 → 适用推进模块依停机规则转态 → 最大速度/签名等更新 → 运动继续积分 → 导弹应用和范围覆盖随之改变。不会瞬间把船速设成 0。

示例：毁电来源本轮缺电 → 激活失败 → 没有本轮毁电事件 → 目标电容可用于维修 → 维修成功 → 生存结果改变。来源、目标都必须是可用世界实体；无限外来干扰只能在明确标注的教学场景中使用。

吸电先按双方当前状态检查条件与例外，再根据实际可抽取量结算。转移、被毁电容、回充、注入和容量溢出分别记账；目标电容不能为负，来源不能无中生有获得超出实际抽取量的电容，溢出有明确去向。

同刻多来源竞争目标资源由统一批次规则解决，不能以 worker 回包先后决定谁抽走了电容。与本轮启动成本、已有到期传电的关系使用战斗时间契约，电容和维修只有一条时间线。

## 7. 观察、脚本与解释

既有 `ActivateModule`、`UseAbility`、`SwitchMode` 足以表达多数电子战操作；参数与能力清单描述目标类型、锁定需求和作用类别，避免为每件装备写一个 JS API。

脚本观察可包含己方允许公开的当前限制、锁定状态、能力可用性、失败收据与可见效果。全知分析可以追踪完整来源与参数，但脚本不能借诊断查询读取隐藏的敌方配装、精确抗性、电容或未被观察到的来源。

能力可用性是查询时刻的状态，不是未来成功承诺；概率结果只有发生后才出现在对应可见事件中。拒绝原因也需要可见性过滤，防止用反复尝试命令探测隐藏状态。

分析接口复用机制查询，并补充：

- `query_control_timeline`：锁定/攻击/导航/跃迁被限制的区间、来源和结束原因。
- `explain_effect_combination`：每个来源的原始强度、范围、抗性、叠加组和最终贡献。
- `query_ewar_cycles`：周期尝试、成功/失败、未能启动原因、资源与目标选择。
- `query_resource_transfers`：毁电/吸电/传电实际量、容量溢出和失败激活。

面板可展示控制覆盖率、破锁次数、重新锁定耗时、被阻止的有效开火周期、减速/签名曲线、毁电引起的维修失败、友方支援抵消程度。覆盖率必须说明对象、时间窗和分母；多来源同时覆盖不重复计时。

“被干扰期间少打了多少轮”是事实统计；“没有干扰时会多造成多少伤害/是否能获胜”是反事实实验。机制收益需从相同检查点、配对种子和明确控制方式比较，不直接把百分比当作等比例 DPS 或胜率收益。

## 8. 架构与组合验收

| 场景 | 必须保证 |
| --- | --- |
| ECM 感应类型/范围/强度变化 | 使用对应感应属性，判定与抽样可复演，重复查询不改结果 |
| ECM 多来源与来源锁定例外 | 每个来源独立生命周期，约束组合和例外不丢失 |
| 范围破锁后重新锁定 | 瞬时破锁不凭空变成持续 ECM；冷却/再次锁定规则准确 |
| 抑阻 × 正在锁定/已锁定 | 距离和扫描分辨率改变按已核准规则更新锁定状态 |
| 炮扰/制导干扰 × 混合武器 | 只影响适用武器/参数，在途参数遵守采样规则 |
| 标记/网子 × 导弹/炮塔/AOE | 实际签名与运动进入后续应用，不能只改展示 |
| 扰频 × 推进/微跳/模式 | 按能力标签与例外施加约束，现有周期按规则停止或完成 |
| 拦截场 × 进入/离开/免疫变化 | 空间成员与能力约束及时更新，目标免疫按机制分类 |
| 毁电/吸电 × 源缺电/目标空电 | 真实激活、条件与资源账本一致，不出现无限外部输入 |
| 多来源叠加 × 停机/死亡/过期 | 精确撤销所属贡献，剩余效果重算，不遗留或重复扣除 |
| 反制/增益 × 减益 | 来源、组、方向与免疫例外可解释；顺序置换不改变结果 |
| 控制无人机/铁骑 × 损失/召回 | 来源生命周期与作用维持策略正确，编队/个体不混淆 |
| 任意上述场景 × 恢复/并行/单步 | 效果实例、锁定进度、随机与队列状态完整恢复，结果一致 |
| 战斗解释 × 玩家观测 | 全知解释不泄露到策略接口，隐藏信息不可从错误原因推断 |

阶段 B 使用合成配方验证：有来源例外的锁定约束、瞬时破锁、带持续时间的属性效果、空间控制场和双实体资源操作。它们证明架构表达能力，不证明真实 EVE 参数。阶段 D 将上述机制逐族绑定数据、核准规则、通过金样和组合测试，再标为已验证支持。
