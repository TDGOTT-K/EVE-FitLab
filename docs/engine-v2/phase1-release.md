# 第一阶段发布收口

基线：用户 2026-09-19 定义的“FitLab 静态配装计算闭环”。六项关闭条件：输入完整、规则完整、指标完整、状态诚实、数据可复现、公开接口可重放。既有 UI 交互及性能是横向验收条件。

用户后续明确：技术闭环之后不能直接发布。当前 UI 只是能力证明；必须先由用户主导重新整理 UI 和设计交互，完成实施及亲自验收，再准备发布。以下技术检查全绿也不替代这一关。

最新引擎专项审计见 [当前 r41 引擎冲刺清单](phase1-engine-audit-r41.md)：3 项有原生 MCP/CLI 证据的 P0 阻断，可以先交给引擎维护任务；不再笼统将所有待办归为 UI 或引擎。

当前结论：**不可正式关闭第一阶段，不可把已接通接口等同于全部验收。** 不以发布压力临时缩小支持范围，不新增缺失游戏机制，不开发战斗沙盒。只修改当前独立副本；本批没有引擎修改。

## 可重复发布检查

运行 `python scripts/check-phase1.py`。使用临时状态目录，按固定列表执行静态产品专项、无头对照、分享/编辑/空值前端测试和模块静态检查；保存每条命令的日志、退出码及耗时到 output/phase1-gate-时间/result.json。任一失败退出非零，不跳过失败套件。

`testsPassed` 只代表这些测试通过；`releaseReady` 在以上阻断关闭前保持 false。脚本不发布、不安装、不修改用户装配库。

## 引擎移交边界

本批引擎契约和实现未变，无需要重放的新增引擎补丁。已有 LOCAL-001～008 仍按副本 docs/ui-local-changes.md 升级核对。现阶段不得把表中的 UI 欠账交给引擎；新机制缺口必须附原生请求、MCP/CLI 回执、受影响静态数值和覆盖诊断后再登记。
