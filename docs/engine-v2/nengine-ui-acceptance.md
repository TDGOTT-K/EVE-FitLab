## 接口与代码边界

- `nengine_bridge.py`：固定副本子进程、初始化、超时、序列化 RPC、契约校验、关闭；无 battle 通路。
- `nengine_adapter.py`：FitLab 装配到 EveFitRequest 的显式映射；技能不丢弃、模式/子系统/实例/副作用/舰载机身份保留。输出判别字段 `provider=nengine`、`contract=fitlab-analysis-v2`，原生报告保留在 native 中。
- `nengine_catalog.py`：读取同一副本的元数据，保留旧浏览器分类导航；不执行数值公式。当前导航目录并不等于新 SDE 全量物品覆盖。
- `nengine-view.js`：原生报告展示，只有格式化，不复制 Dogma、DPS 或电容算法。旧报告仍走旧 presenter，不伪造旧模型所需字段。
- HTTP：GET `/api/catalog`、`/api/fighters`、`/api/engine-status`；POST `/api/analyze`；原保存/角色/方案接口继续负责本地 UI 数据。
- 计算缓存现在包括整个装配输入；新增配置修改不会错误复用旧结果。失效返回值仍按 analysisVersion 丢弃。
- 本批未使用引擎会话事务替代 FitLab 本地保存、撤销与版本控制；这是后续重构项，不声称已完成 fit_create/fit_execute 全链路。
