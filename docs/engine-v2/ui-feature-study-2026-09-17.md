# 新引擎功能 UI 与用户反馈研究

2026-09-17。阅读时 N 引擎 HEAD 为 `b65de4c`。本轮只核对本地源码、契约及文档，不修改引擎、不重新执行引擎测试。以下交互及顺序是建议，未当作用户已确认决定。

## 结论

下一轮建议从 **脑插配置** 开始，再做增效剂、深渊实例、舰体模式和铁骑编队。模式是独立的小任务，可以提前穿插。继续现有 FitLab 的视觉和操作结构，防御区域按用户要求不改。

脑插与增效剂对应明确投诉 F020/F021，比继续美化属性面板更直接。新配置的结果回到已有工作区显示，不再增加重复的数值面板。

## 能力核查与历史修正

- [最终接入审查](../../../N号引擎/docs/ui-entry-final-audit.md)记录 0.158 已关闭 U1–U4，达到“可以考虑接 UI”门槛。早期文档的“UI 门禁未通过”不能继续作为全局结论；这也不等于全机制或实服时序认证。
- [公开契约 r5](../../../N号引擎/contracts/headless-v1/r5/semantics.md)为 `nengine-headless-v1`，首个实现 0.162，声明 21 个工具。README 顶部版本之后仍有火箭与隐形提交，应以实际宿主状态和固定契约判断能力。
- 核对 `src/NEngine.Core/Dogma/EveEditor.cs`，有 `setImplants`、`setBoosters`、`setFighters`、`setTacticalMode` 编辑分支；`EveFitting.cs` 有对应输入和分析。命令存在不代表全部装备家族均已覆盖。
- FitLab 当前装配、角色和情景 UI 未发现这些功能的正式配置入口。已有普通无人机与四类子系统不能算铁骑、脑插、战术模式已支持。
- 现有 FitLab 仍用旧计算链路。新宿主是 MCP stdio，正式接入需要适配桥接，不能直接当作浏览器 HTTP 服务。

## 脑插第一轮设计

1. 驾驶员选择继续负责技能快照；相邻入口显示脑插／增效剂图标与数量，不把长名单塞进顶栏。
2. 脑插页采用紧凑两行槽位卡片，点击空槽只列适用类型。已装卡片提供替换、卸下、信息；套装成员高亮，加成放悬停详情。
3. 复用当前预览、拖动、撤销规则。只显示有内容的行；无子明细的提示不锁定。CPU/PG、DPS、速度、电容变化在既有位置显示。
4. 数据归属建议：角色管理保存技能身份，装配保存本次脑插／增效剂快照，另可保存复用方案。换驾驶员保留装配方案并重新校验技能，避免修改一名角色影响全部装配。此规则在实现时需明确说明，尚未作为既定行为。
5. 分享建议保留计算所需脑插、增效剂和固定副作用配置，驾驶员名称仍可隐藏；本地情景继续不分享。不能因为隐藏姓名就丢掉计算输入。
6. 首轮代表样本：无脑插、单件、Snake 全套／混装／Omega 单独、同槽冲突、缺技能、未覆盖家族、预览取消、应用撤销、换角色与保存往返。

增效剂随后以 Blue Pill 为例，固定副作用选择，不在每次重算时重新抽签。随机服用、剩余时长及跨到期战斗属于实验室；不为静态装配工具引入一套战斗时间线。

## 深渊与铁骑的独立设计要求

- 深渊是物品实例，不是公共类型。同 typeId 不同数值不能合并贡献或共用可变属性；复制、槽位交换、撤销、分享必须保留完整实例。旧格式表示不了时列出损失，不能静默变普通装备。
- F011 的版本导航与深渊实例分开：前者查公共类型的 T1/T2/势力关系，后者选“我拥有的这一件”。版本跳转不能直接替换已装装备。
- 铁骑“拟部署”是静态选择，不是假装正在飞行。舱容、总管数、轻／辅／重上限分别检查，不能相加当总数。
- r5 已增加显式舰载机火箭实验，早期资料“火箭未接入”是历史范围。`loadedCycleDps` 是有弹期间周期值，不能当含召回补给的持续总 DPS。未完整可用时保留分项与原因，不回填零。

## 用户投诉如何约束新设计

来源：[首测反馈台账](../beta-feedback.md)、[原 V2 映射](feedback-mapping.md)，以及本任务后续用户纠正。

| 反馈 | 当前判断与后续要求 |
| --- | --- |
| F006 数量限制 | 本会话已做安装前检查；新入口仍统一事务校验。正式接 N 后以引擎为权威，不能长期维持两套限制公式 |
| F012/F022 预览与校准 | 原位预览已做，但不代表校准专项完成。现有补丁主要覆盖属性／资源区，槽位标题的校准需专项核查；新资源出现／消失也要有差量 |
| F017 未保存仍保留 | 自动恢复草稿仍存在，投诉不能标为解决。新增配置必须说明应用、保存、放弃的边界，不把恢复草稿伪装成正式保存 |
| F018 拖回卸载 | 装备／弹药移动、交换、卸载已做；脑插等入口延续这套操作，不退回长表单 |
| F023/F024 延迟与动画 | 过期结果保护不是性能验收。需要测操作到显示的端到端时间；动画表达真实差量，不能遮掩计算等待 |
| F013/F025/F026 输出说明 | 总值、曲线、DPS/EDPS 已优化；新增贡献依声明范围加入，未知不能补零，火箭周期输出不能冒充持续值 |
| F027/F028/F029 计算投诉 | 导弹技能、无人机技能、含换弹输出继续作为适配验收案例；不能因为新引擎测试总数大就认定这些用户案例均解决 |
| F010/F011/F019 浏览导航 | 逐项核查，类型关系用真实数据，不能名称猜匹配。F011 原文明示需要充分设计，预览／安装不能代替导航 |
| K06 外部传电 | 用户明确情景只判断当前船，不要求双方联算。轻量情景保留持续来源假设；真实来源缺电停机放实验室，不能扩大情景工具 |
| 本会话约束 | 防御不改；小提示少文字、无空行、有子明细才锁定；游戏式拖放优先；情景本地绑定且不分享；DPS 不扣抗性、EDPS 才扣 |

台账多数状态仍停留 2026-09-14 的“待复现／未排期”。本轮不批量改成已解决，避免把局部 UI 实现当成完整回归。F003 等旧故障也仍需单独复核，和新功能设计分开。

## Mock 与接入边界

- 遵照用户要求：无方便旧接口时做独立可替换的 Mock，不扩修旧引擎。目录／槽位可用真实元数据；模拟结果明确标“设计预览／示例”，不混入真实计算总值。
- 每个功能准备可用、冲突、缺技能、未支持四种样本，另有加载与失败。首轮原型不直接改用户现有装配格式；评审交互后再确定持久化与正式接入。
- 正式适配从 `engine_status` 检查契约与能力开始；稳定实例 ID、revision、requestId 与 coverage/error 进入适配层，技术细节留在次级说明。
- N 与旧 FitLab 目录分别固定过 SDE 3503375 与 3248221；跨版本差异不能直接判错，不能静默覆盖旧存档。固定一次实际宿主和契约快照，不拼接不同历史版本的字段。
- 第一份具体交付建议：脑插入口、槽位卡、类型选择、套装提示、预览／应用／撤销和异常状态。使用隔离 Mock 验收，不把旧引擎伪加成当新功能完成。
