# 装配分享长图：调研与首版规格

日期：2026-09-13。阶段：网页首版已实现并验证；未构建安装包。

## 参考与取舍

- https://wiki.eveuniversity.org/PYFA ：查看了装配界面信息分区和导入导出说明。装备、弹药、无人机与技能条件共同决定结果，属性包括抗性/EHP、DPS/齐射、锁定、速度、造价。页面说明的是 EFT 等文本分享，不能据此断言它提供长图导出；且页面提示部分资料需更新。
- https://eveworkbench.com/ ：查看当前首页的公开装配展示。舰船名称、用途名称和 ISK 估价并列，适合作为分享卡片的识别信息。尚未确认其原生图片导出功能。

## 首版交互

装配界面保存旁增加“生成图片”，装配库行右键菜单增加同名入口。打开内部预览弹窗，默认简洁版，可选择完整属性、货舱、备注、是否显示驾驶员名称。预览完成后保存 PNG；复制图片作为浏览器支持时的额外方式，失败仍可保存。

## 长图结构

宽度建议 1080 px，高度随内容增长，不依赖窗口宽度、滚动位置或三栏拖动结果。

1. 顶部：EVE FitLab 标识、舰船官方图片与等级角标、装配名称、标签、参考估价。
2. 核心结果：DPS、EHP、电容稳定/耗尽时间、最大速度；注明当前弹药、超载及技能条件。针对靶标的应用 DPS 单独标注，不混为理论 DPS。
3. 配置清单：子系统、高、中、低、改装件、无人机、可选货舱。装备图标、名称、数量及状态；仅装备、弹药、状态完全相同才合并。无人机分别列携带数量和出动数量。
4. 属性：三层抗性、CPU/能量栅格剩余、射程、回盾/维修、机动、锁定等。简洁版只保留主要结果，完整版增加详细结果。
5. 备注：自动换行、保留段落。
6. 页脚：由 EVE FitLab 生成 · EVE Online 舰船装配模拟器；生成日期和数据版本。有正式发布地址后再增加链接/二维码，不能使用本地地址充当下载入口。

品牌信息常驻头尾，但不使用覆盖装备文字的大水印。

## 数据与实现准备

- 导出开始 structuredClone 当前装配；使用 getCalculation 对同一快照计算，不能截取拖拽预览或使用旧 report。
- 装备名称、官方图标与等级角标复用现有 catalog/资产体系。
- estimateFitPrice 已包含船体、装备、装填弹药、无人机、货舱；复用此口径。标为 ESI 参考估价，显示缺价数量和更新时间；缺价不当作零价。
- 建立独立 share-image.js 数据排版/Canvas 渲染器，先测量行高再创建画布，避免外部字体/图片未加载、隐藏区和滚动容器导致裁切。
- 图片需通过可用于 Canvas 的资源加载方式；若需要本地代理，只允许官方图像域及类型 ID，不做任意 URL 代理。图像失败时保留文字并提示。
- 字体加载完成后绘制；PNG 下载使用 Blob URL 并释放。桌面 CSP 需允许预览 blob: 图像，保存/复制在桌面环境另验。
- 不上传玩家装配；渲染在本机完成。导出不修改装配、历史、保存状态。

## 验收

真实有装备的配置、T3 子系统、混合超载/弹药、无人机多堆叠、长中文名称/备注、缺价及图像失败。生成期间修改配置也不能混入新数据。核对导出结果与同一装配快照计算结果；检查文字不裁切、数量不丢失。分别验证浏览器保存和桌面保存。首版先网页迭代，不打安装包。

## 装配码导入（2026-09-13）

默认完整属性，并补充单件装备资源/输出/射程/周期参数。页尾加入 Q 级纠错二维码，每片 600 字符，白底及静区；gzip 压缩，技能按等级分组和 ID 差分编码，SHA-256 对完整压缩数据作一致性校验。校验不是作者身份签名。EVFL1 格式分片包含同一摘要、序号和总数，缺片或混入另一装配时拒绝导入。

便携字段仅包括舰船、名称、标签、可选备注/驾驶员名称、槽位/弹药/状态、无人机、全部货舱及技能快照；不含本地记录 ID、官网账号授权或外部装配 ID。关闭备注/驾驶员显示时，二维码中也不包含相应文字。外部靶标和传电等关系需要导入后重新设置。所有识别在浏览器本机执行，不把图片上传。

入口：装配库“从图片导入”，支持选择多张图片、拖拽、粘贴图片；缺片可继续补图。校验及引擎检查后提供预览，用户点“导入为新装配”才写入新记录。

已验证帕拉丁 1080×5951 长图：PNG、JPEG quality 55、WebP quality 60、540px 宽 JPEG quality 65、裁剪尾部后缩放加边框的模拟截图均还原成功。实际保存新记录后，21 个槽位（含默认状态归一化）、505 项技能及舱内物品与源记录相同，测试副本已清理。损坏校验、混图、缺片、隐藏名称/备注均有 codec 测试。不能保证任意压缩、过小截图、遮挡或裁掉二维码后仍可读；旧分享图没有编码数据，不能精确导入。尚未打包或验证 Windows 安装版。

依赖源码入口 desktop/qr-vendor-entry.js；运行 npm run build:qr 生成随应用分发的 qr-vendor.js，不依赖 CDN。许可证在 assets/vendor/。测试：npm run test:share-code。

## EVF2 二进制装配码

2026-09-13：新导出默认 EVF2，解码继续支持 EVFL1 文本码。浏览器内部使用 EVFB:Base64 字符串作集合/分片键，二维码实际使用 byte segment 承载原始二进制，不把该 Base64 文本写入二维码。

封包：4 字节 ASCII EVF2；1 字节压缩标志（0 原始、1 gzip）；1 字节分片序号（从 1 开始）；1 字节总数（最多 16）；32 字节完整载荷 SHA-256；最多 600 字节分片内容。所有分片必须版本、压缩标志、摘要和总数相同。校验后再解压和解码；摘要只校验一致性，不证明作者身份。

载荷顺序见 fit-binary.js：舰船 ID；名称、备注、驾驶员名称三个 UTF-8 长度前缀字符串；标签列表；槽位列表；无人机列表；货舱列表；技能分组。所有整数使用最多 5 字节的无符号 LEB128（uint32）。槽位 rack index 低 3 位，state index 高位；另存槽位序号、物品 ID、弹药 ID，0 表示空。技能按等级分组，类型 ID 排序后差分。不使用随 SDE 顺序变化的隐式索引。压缩只有在小于原始载荷时启用。所有列表、字符串、总数据大小受限，并拒绝溢出、截断和未知尾部。

帕拉丁样本（21 槽位、505 项技能）：旧码 2 张、共 1118 字节；新码 1 张、556 字节，减少约 50%。二维码纠错 Q 和白边保持不变。新长图 1080×5941。PNG、JPEG quality 55、WebP quality 60、540px 宽 JPEG quality 65、模拟二次截图全部识别成功，旧版两张码 PNG 也通过。codec 额外覆盖旧版兼容、长备注多片、倒序/重复分片、缺片、损坏、截断、uint32 溢出与隐藏文字。未重新打包 Windows 安装程序。
